CLI ​

This page lists every mcp-lens command with its exact flags and defaults, so you can look one up without re-running --help. For a first run end to end, see Quick Start; for what the report's columns mean, see Reading Reports.

All commands share the same entry point:

mcp-lens <command> [options]

Only scan and auth write to the database, so only they take the writer lease and contend with the VS Code extension. report opens the database but only ever writes an incidental log backfill; if the extension holds the lease it silently skips that save and still prints the same report, read-only. For why a writer lease exists at all, see How It Works.

report ​

mcp-lens report [--days <n>] [--format <f>]

Prints the cost x usage matrix: every scanned tool's definition token cost next to how often it was actually called, with a recommended action per row. This is the default command, so plain mcp-lens runs it too.

OptionDefaultMeaning
--days <n>30Aggregate only the last n days. Must be a number greater than 0.
--format <f>tableOutput format: table, ai, or json.
bash
mcp-lens report --days 14 --format table

The table has eleven columns. This excerpt keeps only 3 of the real rows so the block stays short, but every column is real:

server          tool                     defTokens  calls  respTokens  loaded/sessions  errorRate  errorTokens  action  confidence  reason
--------------  -----------------------  ---------  -----  ----------  ---------------  ---------  -----------  ------  ----------  ------------------------------------------------------------------------------------------------------------------------------------------
web-search      web-search_place_search  17251      0      0           0/533            -          0            remove  medium      definition 17,251 tokens, 0 calls. small savings, but cleans up the search space. 98 sessions/3d observed, confirmed with more observation
knowledge-base  knowledge-base-search    1809       10     124         5/533            0%         0            keep    high        called 10 times
weather-tools   get_weather              74         4      83          3/533            0%         0            keep    high        called 4 times

savings: potential=61893 actual=26839 saved=35054
(0 session files backfilled)

--format ai prints the same data as Markdown, with row-reason templates deduplicated into a "Row reason templates" section above the table. This is the format the /lens-audit slash command consumes, and it is also the shape to paste into a chat with an LLM when you want it to reason about which tools to turn off.

scan ​

mcp-lens scan [--config <path>]

Connects briefly to every configured MCP server, calls tools/list, and records each tool's definition token count. It spends no LLM tokens and never edits a client config file.

OptionDefaultMeaning
--config <path>every detected client configRead and scan only this one config file instead of auto-discovering every client's config.
bash
mcp-lens scan

The discovered: line lists how many servers were found per config source (claude-user, claude-project, codex, gemini), joined with ·. The example below shows the real format with illustrative counts:

discovered: claude-user 2 · codex 1
- web-search: 9 tools, 26198 tokens
- knowledge-base: 15 tools, 24157 tokens

scan writes to the database, so it takes the writer lease. If the VS Code extension currently holds it, the command prints a message and exits with a non-zero status instead of overwriting the extension's observations:

The VS Code extension is writing the MCP Lens DB, so this command cannot run right now.
Close the extension window (or the other running mcp-lens) and try again. It may also clear on its own shortly.

auth ​

mcp-lens auth <serverName> [--clear]

Runs an OAuth login for one HTTP MCP server, then rescans just that server. Use it for servers that require sign-in before tools/list succeeds.

OptionDefaultMeaning
--clearoffDelete the stored credentials for <serverName> instead of logging in.
bash
mcp-lens auth github
github: login complete, 12 tools · 3410 tokens

Like scan, auth writes to the database and takes the writer lease, but only around the final save; the browser sign-in itself happens before the lease is requested, so a slow login does not block the extension. If the server refuses automatic client registration (for example GitHub's or Figma's remote MCP servers), the command prints the config key to set an OAuth client id under, or the header to use a personal access token instead.

hooks status ​

mcp-lens hooks status [--json]

Shows per-client hook installation state: whether the hook package is installed, whether its trust state is approved (Codex only), whether the bundled runner is present, the last observed hook event, how many events are still pending, and an overall health.

OptionDefaultMeaning
--jsonoffPrint the same data as JSON instead of the human-readable form.
bash
mcp-lens hooks status

Field names and shape below are real (one block per client, client / package / trust / runner / last event / pending / fallback / health); the values are illustrative, not a captured run:

Claude Code
  package: installed
  trust: not-required
  runner: ready
  last event: <ISO timestamp of the most recent inbox event, or "none">
  pending: 0
  fallback: unknown
  health: idle

hooks doctor ​

mcp-lens hooks doctor [client]

Diagnoses the hook setup and prints one line per finding, worst severity first. Pass a client name to check only that one.

ArgumentValues
client (optional)claude-code, codex, gemini-cli
bash
mcp-lens hooks doctor codex
[WARNING] codex codex-trust-unapproved: Codex hook trust is not approved; review it with /hooks.

hook capture ​

mcp-lens hook capture --client <c>

This is the hook runtime's entry point, not a command for humans to run directly. Claude Code, Codex, and Gemini CLI invoke it as a lifecycle hook, piping the hook payload to it on stdin. It decodes the payload, queues an observation into ~/.mcplens/inbox, and always prints {} on stdout and exits 0, even when the payload is invalid or --client is missing or unrecognized. This fail-open contract exists so a bug here can never block your coding session.
