# MCP Lens v2 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude Code와 Codex의 모든 세션 사용량을 전역 관찰하고, 정적 참조·호출 연쇄·LLM 의미 분석을 통과한 독립 MCP 툴만 전역에서 가역적으로 차단하며, 직접·간접 후회 신호를 탐지해 즉시 복구할 수 있는 v2 안전 루프를 구현한다.

**Architecture:** `packages/core`가 정의 원문·서버 정체성·분석 캐시·전역 액션 원장·후회 신호의 유일한 도메인 계층이다. `packages/hook-runtime`과 기존 로그 어댑터는 최소한의 관찰 사실만 정규화하고, `packages/extension`은 동의·추론 실행·영문 UI·명령 연결을 담당한다. 공유 계약과 DB 마이그레이션을 먼저 직렬 완료한 뒤 파일 소유권이 분리된 트랙을 병렬 실행하고, `extension.ts`·패키지 매니페스트·실사용자 설정 검증은 마지막 직렬 웨이브에서만 수행한다.

**Tech Stack:** TypeScript strict, Node.js ≥20, npm workspaces, Vitest, sql.js, js-tiktoken, MCP SDK, VS Code Extension API, Claude Code CLI, Codex CLI.

## 1. 기준 문서와 완료 조건

- 설계 기준: `MCP-Lens-설계문서-v2.md`의 승인본, 기준 커밋 `548dccc`.
- 계획 파일: `docs/plans/2026-08-03-mcp-lens-v2-구현계획.md`.
- UI 문자열은 영어로만 작성한다. 설계·계획·개발 문서는 한국어로 작성한다.
- 사용량 집계와 액션 범위는 프로젝트가 아니라 사용자 전역이다.
- Gemini CLI는 사용량 관찰만 유지하며 v2 분석·전역 차단·후회 복구 대상에서 제외한다.
- `Independent`가 아닌 툴에는 전역 차단 명령을 노출하지 않는다.

- 서버 이름이 같고 command/URL 정체성이 다르면 해당 서버의 모든 액션을 전역 차단한다.
- Claude 직접 후회 신호 또는 Codex의 서로 다른 두 세션 간접 신호가 성립하면 해당 액션을 복구 후보로 표시한다.
- Claude와 Codex 설정 수정은 MCP Lens 소유 규칙만 정확히 추가·제거하고, 백업·전후 지문·소유 원장 없이는 복구하지 않는다.
- 전체 단위 테스트, core/extension typecheck, hook 패키지 동기화 검사, workspace build가 통과한다.
- 실제 MCP 서버·실사용자 설정·공유 DB를 쓰는 검증은 Task 14에서만 직렬 실행한다.

## 3. 고정 상수와 정책

| 항목 | 값 | 근거 |
|---|---:|---|
| `ANALYSIS_RULES_VERSION` | `1` | 규칙 전체 무효화 키 |
| 호출 연쇄 관찰 창 | 최근 90일 | 기존 장기 사용량과 계절성 균형 |
| 최소 동시 관찰 세션 | 서로 다른 3세션 | 단발 우연 배제 |
| A-before-B 임계값 | 80% 이상 | 설계 승인값 |
| 반례 해제 조건 | A 없이 B 성공 2세션 이상 | 설계 승인값 |
| Claude batch payload | 정의·집계 토큰 120,000 이하 | Haiku 200k 문맥에 시스템·출력 여유 확보 |
| Codex batch payload | 정의·집계 토큰 200,000 이하 | 장문 입력 비용 경계 아래에서 출력 여유 확보 |
| CLI timeout | 300,000ms | 최초 다중 서버 분석의 상한 |
| 자동 재시도 | 0회 | 비용 예측 가능성 보장 |
| Codex 간접 후회 | 같은 액션, 서로 다른 2세션 | 설계의 Experimental 기준 |
| 백업 보존 | 액션별 1개, 클라이언트별 최근 5개 + 모든 활성 액션 | 설계 승인값과 수동 복구 가능성 |
| 복구 후 재차단 유예 | 같은 definition hash에 7일 | 즉시 재권고 반복 방지; 정의 변경 시 즉시 해제 |

Provider 해석은 명시 설정이면 해당 CLI만 검사한다. `auto`에서 실행 가능한 CLI가 하나면 그것을
선택하고, 둘 다 실행 가능하면 외부 호출 전에 최초 동의 UI에서 Claude/Codex 중 하나를 사용자가
고르게 해 resolved provider/model을 저장한다. 둘 다 없으면 `unavailable`이다. 저장된 동의의
provider/model과 현재 resolved 값이 다르면 동의를 다시 받아야 하며 더 비싼 모델로 자동 대체하지
않는다.
Claude는 빈 임시 디렉토리에서
`claude -p --safe-mode --model haiku --tools "" --no-session-persistence --strict-mcp-config --mcp-config '{}' --output-format json --json-schema <schema>`를
사용한다. `--bare`는 OAuth/keychain 인증을 읽지 않으므로 사용하지 않는다. Codex는 빈 임시
디렉토리에서
`codex exec -C <dir> -m gpt-5.6-luna -c 'model_reasoning_effort="low"' -s read-only --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check --output-schema <schema> -`를
사용한다. 두 프로세스 모두 JSON payload를 stdin으로 받고, 환경에는 인증에 필요한 기존 값만
상속하며 프로젝트 경로·본문을 프롬프트에 넣지 않는다.

`AdapterResult`에는 `toolSearchAttempts?: ToolSearchAttempt[]`만 추가한다. Claude 직접 신호는
`PreToolUse → tool-before` 또는 transcript의 구조화된 MCP `tool-failure`/`tool-after` 관찰과 활성
Claude action의 정확 일치로 만든다. 실제 Claude Code에서는 `permissions.deny`가 `PreToolUse`보다
먼저 적용되는 실행 경로가 있으므로 log 결과를 동등한 attempt 증거로 사용하되, generic log load는
제외한다. `PermissionDenied`와 오류 원문에는 의존하지 않는다. 원문 tool input·script·출력은 DB에
저장하지 않는다.

### 4-1. DB DDL

`schema.sql`에 다음 테이블과 인덱스를 추가한다. 기존 테이블은 삭제하거나 재작성하지 않는다.

```sql
CREATE TABLE IF NOT EXISTS server_identities (
  client TEXT NOT NULL, server_name TEXT NOT NULL, source_kind TEXT NOT NULL,
  source_path_hash TEXT NOT NULL, transport TEXT NOT NULL, endpoint_hash TEXT NOT NULL,
  conflict_state TEXT NOT NULL, observed_at TEXT NOT NULL,
  PRIMARY KEY (client, server_name, source_kind, source_path_hash)
);
CREATE INDEX IF NOT EXISTS idx_server_identity_name ON server_identities(server_name);

CREATE TABLE IF NOT EXISTS tool_definition_bodies (
  server_name TEXT NOT NULL, tool_name TEXT NOT NULL, description TEXT,
  input_schema_json TEXT NOT NULL, definition_tokens INTEGER NOT NULL,
  definition_set_hash TEXT NOT NULL, scanned_at TEXT NOT NULL,
  PRIMARY KEY (server_name, tool_name)
);
CREATE INDEX IF NOT EXISTS idx_definition_set_hash ON tool_definition_bodies(definition_set_hash);

CREATE TABLE IF NOT EXISTS dependency_analyses (
  definition_set_hash TEXT NOT NULL, analysis_rules_version INTEGER NOT NULL,
  provider TEXT NOT NULL, model TEXT NOT NULL, status TEXT NOT NULL,
  analyzed_at TEXT NOT NULL, error_code TEXT,
  PRIMARY KEY (definition_set_hash, analysis_rules_version)
);
CREATE TABLE IF NOT EXISTS tool_dependency_results (
  definition_set_hash TEXT NOT NULL, analysis_rules_version INTEGER NOT NULL,
  server_name TEXT NOT NULL, tool_name TEXT NOT NULL, status TEXT NOT NULL,
  depended_on_by_json TEXT NOT NULL, rationale TEXT NOT NULL,
  PRIMARY KEY (definition_set_hash, analysis_rules_version, server_name, tool_name)
);
CREATE TABLE IF NOT EXISTS tool_explanations (
  definition_set_hash TEXT NOT NULL, analysis_rules_version INTEGER NOT NULL,
  server_name TEXT NOT NULL, tool_name TEXT NOT NULL, display_summary TEXT NOT NULL,
  what_you_lose TEXT NOT NULL, risk_without_tool TEXT NOT NULL,
  PRIMARY KEY (definition_set_hash, analysis_rules_version, server_name, tool_name)
);

CREATE TABLE IF NOT EXISTS global_actions (
  action_id TEXT PRIMARY KEY, client TEXT NOT NULL, server_name TEXT NOT NULL,
  tool_name TEXT NOT NULL, identity_hash TEXT NOT NULL, definition_set_hash TEXT NOT NULL,
  owned_rule TEXT NOT NULL,
  backup_path TEXT NOT NULL, pre_fingerprint TEXT NOT NULL, post_fingerprint TEXT NOT NULL,
  status TEXT NOT NULL, created_at TEXT NOT NULL, restored_at TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_one_active_global_action
  ON global_actions(client, server_name, tool_name) WHERE status='active';
CREATE TABLE IF NOT EXISTS regret_signals (
  action_id TEXT NOT NULL, kind TEXT NOT NULL, session_id TEXT NOT NULL,
  observed_at TEXT NOT NULL,
  PRIMARY KEY (action_id, kind, session_id)
);
CREATE TABLE IF NOT EXISTS inference_consents (
  policy_version INTEGER PRIMARY KEY, provider TEXT NOT NULL, model TEXT NOT NULL,
  status TEXT NOT NULL, accepted_at TEXT NOT NULL, revoked_at TEXT
);
```

### 4-2. `LensStore` 공개 API

```ts
upsertServerIdentities(rows: readonly ServerIdentity[]): void;
serverIdentities(serverName?: string): ServerIdentity[];
upsertDefinitionBodies(rows: readonly ToolDefinitionBody[]): void;
upsertScanResult(definitions: readonly ToolDefinition[], bodies: readonly ToolDefinitionBody[], identities: readonly ServerIdentity[]): void;
definitionBodiesForServer(serverName: string): ToolDefinitionBody[];
dependencyCallsSince(iso: string): DependencyCallRecord[];
findDependencyAnalysis(definitionSetHash: string, rulesVersion: number): DependencyAnalysis | null;
saveDependencyAnalysis(analysis: DependencyAnalysis): void;
recordGlobalAction(action: GlobalAction): void;
activeActionFor(client: GlobalActionClient, serverName: string, toolName: string): GlobalAction | null;
activeActions(): GlobalAction[];
updateGlobalActionStatus(actionId: string, status: GlobalActionStatus, restoredAt?: string): void;
recordRegretSignal(signal: RegretSignal): void;
regretSignals(actionId: string): RegretSignal[];
saveInferenceConsent(consent: InferenceConsent): void;
currentInferenceConsent(policyVersion: number): InferenceConsent | null;
```

`saveDependencyAnalysis`는 분석·결과·설명을 한 트랜잭션에서 교체한다. `dependencyCallsSince`는
`ORDER BY session_id, called_at, id`이고 `tool_calls.id`를 `sequence`로 반환한다. Codex
`toolSearchAttempts` 중 활성 액션의 현재 Codex 노출명 `mcp__${serverName}__${toolName}`과 정확히 같은 항목만
`indirect` 신호로 저장한다. 정규화가 관찰되지 않은 서버명은 fuzzy matching하지 않아 false negative로
남긴다.
Claude `tool-before` 중 활성 Claude action의 server/tool과 정확히 일치하고 action 생성 이후에
관찰된 항목만 `direct` 신호로 저장한다.

### 20-1. 사용 방법과 공통 안전 규칙

아래 각 코드 블록은 **독립된 한국어 실행 프롬프트**다. 사람은 프로젝트 루트에서 Codex/Claude Code 오케스트레이터를 열고, 해당 블록 하나만 그대로 붙여넣는다. 사람이 `git`·worktree·브랜치 명령을 따로 실행할 필요가 없으며, 다른 블록이나 표를 참조할 필요도 없다. 모든 블록은 현재 `HEAD`를 `MCPLENS_BASE`로 기록한 뒤 worktree를 만들고, 그 worktree에서 검증한 후 역할 고정 자식을 포그라운드로 실행한다.

각 후속 프롬프트의 선행 merge 조건은 오케스트레이터가 `MCPLENS_BASE`를 기록하기 전 확인한다. `docs/task-integration-ledger.tsv`에서 선행 태스크의 통합 커밋 SHA를 읽고, `git cat-file -e "${TASK_SHA}^{commit}"`와 `git merge-base --is-ancestor "$TASK_SHA" HEAD`가 모두 성공해야 한다. 구현 브랜치와 worktree의 존재 여부는 게이트가 아니다. 통합 직후 메인 오케스트레이터는 해당 SHA를 이 대장에 추가해 문서 커밋으로 보존한다. 조건이 충족되지 않거나 worktree 생성·검증이 실패하면 어떠한 수정·커밋·merge·push도 하지 않고 `BLOCKED`로 끝낸다.

## 22. 중단 조건

다음은 추정으로 우회하지 않고 `BLOCKED`로 보고한다.

- 실제 Claude PreToolUse payload가 기존 fixture 계약과 달라 tool name 또는 session id를 안전하게 추출할 수 없음.
- 현재 Codex 실제 로그에 exact lookup과 no-match output을 같은 call id로 상관할 수 있는 정보가 없음.
- 사용자 설정이 parse 불가하거나 managed policy로 잠겨 원자적 쓰기·복구가 불가능함.
- server identity collision이 실제 사용자 설정에서 해소되지 않음.
- 지정 모델 또는 structured output 옵션이 설치된 CLI에서 지원되지 않음.
- action 후 fresh session을 만들 수 없거나 hook/plugin trust가 비정상임.
- reviewer `CHANGES_REQUIRED` 또는 verifier `FAIL`이 남아 있음.

이 조건 외의 테스트 실패·타입 오류·fixture 불일치는 해당 태스크에서 수정하고 다시 검증한다.
