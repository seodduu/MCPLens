# Wave 3 결함 F 보정 구현 계획 — 수집 건강도의 훅 커버리지 게이트

4차 E2E 이후 "첫 설치 사용자" 재현 실험에서 결함 하나가 드러났다. 툴 단계 hook이 붙지 않은
클라이언트는 로그 수집이 완전히 정상이어도 수집 건강도가 영구히 `degraded`로 굳고, 그 결과
전역 액션이 영원히 차단된다.

기점 커밋은 이 계획서를 커밋한 시점의 HEAD다.

## 관측된 사실

실기기 codex의 관측 분포(실측):

| source | phase | 건수 |
|---|---|---|
| hook | session-start | 4 |
| hook | turn-stop | 7 |
| hook | **툴 단계(tool-before/after/failure)** | **0** |
| log | tool-before | 57 |
| log | tool-after | 105 |
| log | tool-failure | 5 |

이 상태를 `deriveCollectionHealth`에 그대로 넣으면 `health: 'degraded'`,
`consecutiveMisses: 110`이 나온다.

결정적인 것은 **hook 관측을 전부 제거해도(= 훅을 아예 설치하지 않은 사용자를 가정해도)
여전히 `degraded`가 나온다**는 점이다. 즉 이것은 codex 고유의 문제가 아니라, 훅 없이 로그만으로
운용하는 모든 사용자에게 해당한다.

## 원인

`collectionHealth.ts:111`의 miss 판정이 무조건적이다.

```ts
} else if (now - observation.time >= CORRELATION_GRACE_MS) {
  outcomes.push({ kind: 'miss', time: observation.time });
}
```

"log에 완료 호출이 있는데 짝지을 hook이 없다"를 곧바로 miss로 센다. 여기엔 **"hook이 원래
이 툴 단계를 커버하고 있었다"**는 전제가 깔려 있는데, 그 전제를 아무도 검사하지 않는다.

`eligibility.ts:32`는 `log-only`를 정상으로 인정한다.

```ts
if (input.collectionHealth !== 'healthy' && input.collectionHealth !== 'log-only') {
  reasons.push('collection-health-unsafe');
}
```

훅 없이 로그만으로 운용하는 사용자를 위해 의도적으로 열어둔 경로다. 그런데
`collectionHealth.ts:136-142`의 판정 순서에서 `degraded`가 `log-only`보다 먼저 이긴다.

```ts
if (unavailable) health = 'unavailable';
else if (degraded) health = 'degraded';       // ← 여기서 이겨버린다
else if (hookObserved && logObserved) health = 'healthy';
else if (hookObserved) health = 'hook-only';
else if (logObserved) health = 'log-only';    // ← 도달 불가
```

툴 호출이 3건만 쌓여도 `degraded`가 되므로 **`log-only`에 영원히 도달할 수 없다.** 열어둔
경로가 실제로는 닫혀 있었다.

codex의 훅 신뢰가 불안정한 것은 사실이지만, 그것을 "수집기 장애"로 오판해 사용자를 가둔 것은
이쪽 로직이다.

## 설계 판단: `degraded`의 의미를 좁힌다

`degraded`가 뜻해야 하는 것은 **"돌고 있던 hook 수집기가 멈췄다"**는 회귀 신호다.
"hook이 애초에 붙지 않았다"는 장애가 아니라 운용 형태이고, 그것은 이미 `log-only`라는
이름으로 인정되고 있다.

따라서 **툴 단계 hook이 한 번이라도 관측된 적이 있을 때만 `degraded`로 승격한다.**
라이프사이클 hook(`session-start`/`turn-stop`)은 근거로 삼지 않는다. 그것은 툴 단계 커버리지를
전혀 증명하지 못하며, 이번 사고의 핵심이 정확히 그 오인이었다(라이프사이클 hook이 있다는
이유로 `hookObserved`가 참이 되어 `log-only` 라벨조차 못 받았다).

### miss 계수 자체는 건드리지 않는다

`consecutiveMisses`는 "짝을 못 찾고 유예를 넘긴 log 완료"라는 뜻 그대로 유지한다. 게이트는
**`degraded` 승격에만** 건다. 이유는 두 가지다.

1. 기존 사양이 miss 계수의 성숙 시점(유예 경계)을 별도로 못박고 있다
   (`matures an unmatched log observation at the exact grace boundary`가 hook 0건 상태에서
   `consecutiveMisses: 1`을 요구한다). 계수 자체를 건너뛰면 이 사양이 깨진다.
2. 진단 값으로서의 miss 계수는 여전히 유용하다. 사용자에게 "짝이 안 맞은 호출이 N건"이라고
   보여주는 것과 "수집기가 고장났다"고 판정하는 것은 다른 층위다.

### 라벨도 정직하게 고친다

툴 단계 hook 커버리지가 성립한 적 없으면, 라이프사이클 hook이 있더라도 툴 상관 관점에서는
log 단독 운용이다. 이 경우 `healthy`가 아니라 `log-only`로 표기한다. `healthy`라고 표기하면
"hook+로그 양쪽이 정상"이라는 거짓 정보를 준다(실기기 codex가 정확히 이 상태였다).

### 변경 2: 커버리지 성립 여부를 계산한다

hook 후보 수집 루프(`:88-96`) 직후에 넣는다. 루프를 새로 돌지 않고 기존 맵에서 판정한다.

```ts

  // 이 맵이 비어 있다는 것은 툴 단계 hook을 한 번도 못 봤다는 뜻이다.
```

주의: `hookTimesByKey`는 `correlationKey !== null`인 것만 담는다. 상관키 없는 툴 단계 hook은
어차피 짝을 지을 수 없어 커버리지 근거가 되지 못하므로 이 판정으로 충분하다.

### 변경 3: `degraded` 승격에 게이트를 건다

`:128`의 승격 조건만 바꾼다. 회복 조건(`:132`)은 그대로 둔다.

```ts
  for (const outcome of outcomes) {
    if (outcome.kind === 'miss') {
      consecutiveMisses++;
      consecutiveMatches = 0;
      // 툴 단계 hook을 한 번도 못 본 클라이언트에서 miss는 수집기 장애의 증거가 아니다.
      // hook 없이 로그만으로 운용하는 정상 형태이며, 그것은 log-only로 표기된다.
      // 이 게이트가 없으면 그런 사용자는 툴 호출 3건만에 영구 degraded가 되어
      // eligibility가 열어둔 log-only 경로에 영원히 도달하지 못한다.
      if (toolHookCoverageObserved && consecutiveMisses >= MISSES_TO_DEGRADE) degraded = true;
    } else {
      consecutiveMatches++;
      consecutiveMisses = 0;
      if (degraded && consecutiveMatches >= MATCHES_TO_RECOVER) degraded = false;
    }
  }
```

## 이 계획이 다루지 않는 것

**codex의 훅 신뢰(persisted hook trust) 메커니즘.** codex CLI가 `pre_tool_use`/`post_tool_use`
훅을 `/hooks` 화면에 `Active`로 표시하면서도 실제로는 실행하지 않는 현상은 이 저장소 밖의
문제다(`--dangerously-bypass-hook-trust` 플래그의 존재가 그 신뢰 게이트를 뒷받침한다).
이번 보정은 "훅이 안 붙어도 로그만으로 정상 동작해야 한다"는 쪽을 고치는 것이지, 훅을
붙게 만드는 것이 아니다. 훅 신뢰 문제는 별도 조사 대상으로 남긴다.

**`eligibility.ts`.** `log-only`를 이미 정상으로 인정하고 있으므로 고칠 것이 없다.
이번 보정으로 그 경로가 비로소 실제로 도달 가능해진다.
