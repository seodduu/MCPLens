## 1. 실행 모델

### T1 툴 단위 규칙 (설계 3.1·3.2)

`evidence.ts`:

```ts
export function toolEvidence(
  serverName: string,
  toolName: string,
  definitionTokens: number | null,
  ctx: EvidenceContext,
  mode: SessionMeta['mode'] = 'UPFRONT',
): RecommendationEvidence
```

세션 루프에서 모드 게이트 **앞**에 창 안 세션을 센다:

```ts
let windowSessions = 0;
// ...
for (const s of ctx.sessions) {
  const at = ms(s.startedAt);
  const inWindow = at == null
    || (at >= windowStart && (windowEnd == null || at <= windowEnd));
  if (!inWindow) continue;
  windowSessions++;
  if (s.mode !== 'UPFRONT') {
    if (s.mode === 'DEFERRED_OPAQUE') continue;
    if (loaded === undefined || !loaded.has(s.sessionId)) continue;
  }
  observedSessions++;
  if (at != null) datedObservedSessions++;
}
```

기존 루프의 의미(startedAt null은 세되 dated에 안 넣음, 창 밖은 건너뜀)를 유지한 채 순서만
바꾼 것이다. `windowStart == null`이면 루프를 돌지 않고 `windowSessions = 0`.

비용:

```ts
const deferred = mode === 'DEFERRED_MEASURABLE' || mode === 'DEFERRED_ESTIMATED';
const costPerSession =
  definitionTokens == null ? null
  : !deferred ? definitionTokens
  : windowSessions === 0 ? null
  : Math.round(definitionTokens * observedSessions / windowSessions);
const totalObservedCost =
  definitionTokens == null || windowStart == null ? null : definitionTokens * observedSessions;
```

`DEFERRED_OPAQUE`는 `deferred`가 아니므로 UPFRONT 식을 따른다(기존 동작 유지. OPAQUE는 어차피
`not measurable`이다).

`engine.ts` `recommend`: `toolEvidence(..., ctx, mode)`로 호출. `callCount === 0 &&
definitionTokens != null` 분기 맨 앞에:

```ts
const deferred = mode === 'DEFERRED_MEASURABLE' || mode === 'DEFERRED_ESTIMATED';
if (deferred && row.loadedSessionCount === 0) {
  const reasonParts: RecommendationReason = {
    basis: `never loaded in ${evidence.windowSessions} sessions under deferred loading, so there is no evidence yet`,
    serverBasis: null, effect: null, caveat: null,
  };
  return { action: 'unobserved', confidence: 'low', reason: joinReason(reasonParts), reasonParts,
    evidenceLabel, evidence };
}
```

`sizePhrase`를 바꾼다:

```ts
const sizePhrase = (t: number) =>
  mode === 'UPFRONT'
    ? `about ${formatTokens(t)} tokens saved per session when removed`
    : deferred
      ? `pulled in by search in ${evidence.observedSessions} of ${evidence.windowSessions} sessions, `
        + `about ${formatTokens(t)} tokens each time. Removing saves about `
        + `${formatTokens(evidence.costPerSession ?? 0)} tokens per session and cleans up the search space`
      : `small savings, but cleans up the search space`;
```

`pollutionSuffix`는 deferred `remove`·`filter-server`에서는 이미 문구에 담겼으므로 `deferred`일 때
빈 문자열로 둔다.

테스트 `evidence.test.ts` (추가):

- `windowSessions counts every in-window session before the mode gate`: deferred 세션 10개, 로드
  3개 → `windowSessions 10`, `observedSessions 3`.
- `deferred costPerSession amortises the definition over the window`: 위 상황, 정의 800 →
  `costPerSession 240`, `totalObservedCost 2400`.
- `upfront costPerSession stays the definition size`: UPFRONT 10세션, 정의 800 → 800, total 8000.
- `deferred tool with no window has null costPerSession`: 정의 없음(`definitionTokens null`) → null.

테스트 `engine.test.ts` (추가, describe `'deferred basis (design 2026-08-31)'`):

- `never-loaded tool under deferred loading is unobserved, not remove`: DEFERRED_MEASURABLE 10세션,
  정의 있음, 로드 0, 호출 0 → `action 'unobserved'`, `confidence 'low'`, reason에
  `never loaded in 10 sessions` 포함.
- `loaded-but-uncalled tool under deferred loading is remove graded by loaded sessions`: 로드 3세션
  → `action 'remove'`, `confidence 'low'`(3 < 5), `evidence.observedSessions 3`, reason에
  `pulled in by search in 3 of 10 sessions` 포함. 로드 6세션·정의 firstScannedAt이 창보다 3일
  이상 앞 → `medium`.
- `upfront rule unchanged`: UPFRONT 10세션, 로드 0, 호출 0 → `remove`(회귀).
- `filter-server still applies under deferred loading when the server is wide`: 툴 12개 서버,
  1개 호출됨, 나머지 중 로드된 것 → `filter-server`, 로드 0인 것 → `unobserved`.

검증: `npx tsc --noEmit -p packages/core/tsconfig.json`, `npm test`.

### T2 서버 단위 판정 (설계 3.3)

신규 `packages/core/src/engine/serverVerdict.ts`:

```ts
import type { EngineInput } from './engine.js';
import type { RecommendationConfidence, ServerEvidence, ServerVerdict, SessionMeta } from '../types.js';
import { instructionsTokensByServer } from './cost.js';
import { formatTokens } from './format.js';

const MS_PER_DAY = 86_400_000;
const LOW_SESSIONS = 5;
const LOW_DAYS = 3;
const HIGH_SESSIONS = 10;
const HIGH_DAYS = 7;

export function serverRemoveConfidence(ev: ServerEvidence): RecommendationConfidence {
  if (ev.configuredSessions < LOW_SESSIONS) return 'low';
  if (ev.observedDays == null || ev.observedDays < LOW_DAYS) return 'low';
  if (ev.configuredSessions >= HIGH_SESSIONS
    && ev.datedConfiguredSessions >= HIGH_SESSIONS
    && ev.observedDays >= HIGH_DAYS) return 'high';
  return 'medium';
}

export function buildServerVerdicts(input: EngineInput): ServerVerdict[]
```

`buildServerVerdicts` 절차 (전량):

1. `servers` = `definitions`의 serverName 집합, 이름순.
2. 지배 모드 = `dominantMode(input.sessions)` (engine.ts에서 import).
   `deferred = 지배 모드가 DEFERRED_MEASURABLE 또는 DEFERRED_ESTIMATED`.
3. 서버별 창 시작: `min(그 서버 정의들의 firstScannedAt 중 최소, 그 서버 툴의 호출·로드가 있는
   세션의 startedAt 중 최소)`. 둘 다 없으면 그 서버는 `keep`/`high`/증거 0으로 두고 reason은
   `no observation window`. (정의는 있으므로 실제로는 firstScannedAt이 항상 있다.)
4. 창 끝 = 모든 세션의 startedAt 최대.
5. 설정된 세션 판정: `input.serversByClient`가 있고 `size > 0`이면
   `serversByClient.get(s.client)?.has(server)`, 아니면 true.
6. 세션 루프: 창 밖이면 건너뜀(startedAt null은 창 안으로 침). `DEFERRED_OPAQUE`면 건너뜀.
   설정 안 됐으면 건너뜀. `configuredSessions++`, startedAt이 있으면
   `datedConfiguredSessions++`.
7. `loadedSessions` = 창 안 세션 중 그 서버 로드(serverName 일치)가 있는 sessionId 수.
   `calledSessions` = 호출이 있는 sessionId 수.
8. `observedDays` = `configuredSessions === 0 ? null : max(0, floor((windowEnd − windowStart)/DAY))`.
9. `lastActivityAt` = max(창 안 호출의 calledAt, 창 안 로드가 있는 세션의 startedAt,
   `input.lastCallByTool`에서 그 서버 툴 키들의 값). 문자열 비교가 아니라 `Date.parse`로 비교.
10. 판정과 등급은 설계 3.3. `measuredPerSessionTokens` =
    `deferred ? instructions : Σ definitionTokens + instructions`, `instructions` =
    `instructionsTokensByServer(input.serverOverheads ?? []).get(server) ?? 0`.
    `unmeasuredNameListEntries = deferred ? 정의 수 : 0`.
11. reason 문자열은 설계 3.3 그대로. `observedDays`가 null이면 `/{d}d`를 뺀다.

`index.ts`에 `export * from './engine/serverVerdict.js';` 추가.

테스트 `serverVerdict.test.ts` (전량):

- `server never loaded or called under deferred loading is remove-server, counting every configured session`:
  DEFERRED_MEASURABLE 10세션(하루 간격), 서버 `jira` 툴 3개 firstScannedAt = 창 시작 − 10일, 로드
  0, 호출 0 → `action 'remove-server'`, `evidence.configuredSessions 10`,
  `datedConfiguredSessions 10`, `observedDays 9`, `confidence 'high'`,
  `unmeasuredNameListEntries 3`, `measuredPerSessionTokens 0`(오버헤드 없음).
- `instructions overhead is the measured saving under deferred loading`: 위 + `serverOverheads`
  jira 120 → `measuredPerSessionTokens 120`.
- `definitions plus instructions under upfront loading`: UPFRONT, 정의 800×3, 오버헤드 120 →
  2520, `unmeasuredNameListEntries 0`.
- `one load anywhere in the window keeps the server`: 로드 1건 → `keep`, `confidence 'high'`,
  reason `loaded in 1 sessions, never called`, `lastActivityAt` = 그 세션 startedAt.
- `a call keeps the server and names the session count`: 호출 2세션 → reason `called in 2 sessions`.
- `all-time call history outside the window keeps the server`: 창 안 활동 0, `lastCallByTool`에
  `jira t1` → `keep`.
- `configured sessions follow serversByClient when present`: 세션 10개 중 클라이언트 `codex` 4개,
  `serversByClient = { 'claude-code': {jira} }` → `configuredSessions 6`.
- `opaque sessions never count`: DEFERRED_OPAQUE 10세션 → `configuredSessions 0`, `confidence 'low'`.
- `grades`: 4세션 → low; 6세션 3일 → medium; 10세션 7일 → high.

검증: `npx tsc --noEmit -p packages/core/tsconfig.json`, `npm test`.
