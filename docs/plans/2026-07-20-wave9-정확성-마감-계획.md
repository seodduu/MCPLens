### Step 4: engine 구현 (sessionSavings 교체)

```ts
export function sessionSavings(input: EngineInput) {
  const potentialTokens = input.definitions.reduce((s, d) => s + d.definitionTokens, 0);
  const defTokens = new Map(input.definitions.map(
    (d) => [`${d.serverName} ${d.toolName}`, d.definitionTokens]));
  // 키(서버/툴) 단위: 직접 기록이 있으면 직접값, 없으면 정의 조인값.
  // 정의가 없는 서버(스캔 미커버)의 로드는 비교집합 밖 — 제외.
  const perKey = new Map<string, number>();
  for (const l of input.loads) {
    const k = `${l.serverName ?? ''} ${l.toolName}`;
    if (!defTokens.has(k)) continue;               // 비교집합 일치
    const direct = l.loadedTokens;
    const joined = defTokens.get(k)!;
    const v = direct != null && direct > 0 ? direct : joined;
    // 같은 키가 여러 세션에서 로드돼도 정의는 1회분만 계상 (세션 단위 평균 개념은 로드맵)
    if (!perKey.has(k) || v > perKey.get(k)!) perKey.set(k, Math.min(v, Math.max(direct ?? 0, joined)));
  }
  let actualTokens = 0;
  for (const v of perKey.values()) actualTokens += v;
  return { potentialTokens, actualTokens,
    savedTokens: Math.max(0, potentialTokens - actualTokens) };
}
```
(구현 세부는 테스트 3케이스를 통과하는 최소로 조정 가능 — 계약은 테스트가 정의한다.)

### Step 5: 기존 테스트 영향 확인

기존 `sessionSavings` 테스트("잠재 = 정의 전량, 실비용 = 로드분")는 정의 있는 서버만 쓰므로 그대로 통과해야 한다. 통과 못 하면 기대값이 옛 버그를 박제한 것인지 검토 후 보고.
