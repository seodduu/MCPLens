# 온보딩 워크스루와 Setup Status 뷰 구현계획

> **에이전트 실행자에게:** 이 계획은 `superpowers:subagent-driven-development`로 태스크 단위 실행한다.
> 메인 세션은 오케스트레이터다. 스텝은 체크박스로 추적한다.

**설계 문서:** `docs/designs/2026-08-05-온보딩-워크스루-설계.md` (도메인·문구·상태표의 유일한 진실)

**목표:** 확장 설치 후 필요한 4단계(스캔·훅·분석·전역 조치)를 VS Code 네이티브 워크스루로 안내하고,
그 상태를 Setup Status 뷰가 계속 보여준다.

**접근:** 워크스루는 `contributes.walkthroughs` 기여만으로 만든다(웹뷰 없음). 스텝 완료는 커맨드
실행이 아니라 확장이 실제 상태를 판정해 켜는 컨텍스트 키로 판정하고, 조건이 풀리면
`welcome.markStepIncomplete`로 되돌린다. 판정 로직은 vscode를 import하지 않는 순수 모듈로 분리해
유닛테스트한다.

**스택:** TypeScript, npm workspaces, vitest, sql.js(`packages/core`), VS Code Extension API.

## Global Constraints

- 확장의 **사용자 노출 문자열은 전부 영어**다. 코드 주석·커밋 메시지·`docs/` 문서·테스트 이름은 한국어.
- 자기 태스크의 Files 목록 밖 파일을 수정하지 않는다. `packages/core/src/types.ts`와
  루트 설정(`package.json`, `tsconfig.base.json`, `vitest.config.ts`)은 이 계획의 어느 태스크도 건드리지 않는다.
- 유닛테스트는 `fixtures/` + `:memory:` DB만 쓴다. 실 DB(`~/.mcplens/lens.db`)와 실제 MCP 서버 기동은
  Task 7(직렬 전용 웨이브)에서만 만진다.
- 타입체크는 반드시 `-p`로 돌린다. `npx tsc --noEmit -p packages/core/tsconfig.json`,
  `npx tsc --noEmit -p packages/extension/tsconfig.json`. 루트에서 `npx tsc --noEmit`은 0개 파일을
  검사하고 성공하므로 판정 근거가 못 된다.
- 테스트 판정 기준은 항상 `npm test`.
- 워크스루 스텝 id 접두사는 `seodduu.mcp-context-lens#mcpLens.setup#`이다
  (`${publisher}.${name}#${walkthroughId}#${stepId}`).
- `packages/core`는 `vscode`를 import하지 않는다.

`store.ts`의 `currentInferenceConsent` 아래에 넣는다. upsert는 같은 파일의 `setCursor`가 쓰는
`ON CONFLICT ... DO UPDATE` 형태를 그대로 따른다.

```ts
export type ServerScanStatusKind = 'ok' | 'auth-required' | 'failed';

export interface ServerScanStatus {
  status: ServerScanStatusKind;
  scannedAt: string;
  errorCode?: string;
}
```

```ts
  /**
   * 서버별 마지막 스캔 결과. 시각은 호출자가 넘긴다 — 저장소가 시계를 읽으면
   * 테스트가 시각을 고정할 수 없다.
   */
  recordServerScanStatus(
    serverName: string,
    status: ServerScanStatusKind,
    scannedAt: string,
    errorCode?: string,
  ): void {
    this.run(
      `INSERT INTO server_scan_status(server_name, status, scanned_at, error_code)
       VALUES(?,?,?,?)
       ON CONFLICT(server_name) DO UPDATE SET
         status=excluded.status, scanned_at=excluded.scanned_at, error_code=excluded.error_code`,
      [serverName, status, scannedAt, errorCode ?? null]);
  }

  /** 스캔한 적 없는 서버는 '값'이 아니라 '행의 부재'로 표현한다. */
  serverScanStatuses(): ReadonlyMap<string, ServerScanStatus> {
    const map = new Map<string, ServerScanStatus>();
    for (const r of this.select('SELECT * FROM server_scan_status', [])) {
      map.set(r.server_name as string, {
        status: r.status as ServerScanStatusKind,
        scannedAt: r.scanned_at as string,
        errorCode: (r.error_code as string | null) ?? undefined,
      });
    }
    return map;
  }
```

두 타입은 `packages/core`의 공개 API로 내보낸다. `packages/core/src/index.ts`가 `store.ts`를
재수출하는 방식을 그대로 따르고, 개별 심볼을 나열하는 방식이면 두 타입 이름을 추가한다.

```ts
import type { InstallState } from './hookInstall.js';

export interface SetupKeys {
  scanReady: boolean;
  hooksReady: boolean;
  analysisReady: boolean;
}

export interface SetupKeyInput {
  /** 감지 결과. client-missing은 판정에서 제외한다 */
  installs: readonly { install: InstallState | string }[];
  definitionCount: number;
  consentAccepted: boolean;
  analyzedServerCount: number;
}

const STEP_PREFIX = 'seodduu.mcp-context-lens#mcpLens.setup#';

export const SETUP_STEP_IDS: Record<keyof SetupKeys, string> = {
  scanReady: `${STEP_PREFIX}scan`,
  hooksReady: `${STEP_PREFIX}hooks`,
  analysisReady: `${STEP_PREFIX}analyze`,
};

export function evaluateSetupKeys(input: SetupKeyInput): SetupKeys {
  // 설치되지 않은 클라이언트는 사용자가 할 일이 없다 — 판정 모수에서 뺀다.
  const present = input.installs.filter((row) => row.install !== 'client-missing');
  return {
    scanReady: input.definitionCount > 0,
    // needs-approval을 참으로 세면 수집 0건인데 체크가 켜지는 거짓 성공이 난다.
    hooksReady: present.length > 0 && present.every((row) => row.install === 'installed'),
    analysisReady: input.consentAccepted && input.analyzedServerCount > 0,
  };
}

/**
 * 참에서 거짓으로 바뀐 키의 스텝 id.
 * 거짓인 동안 매번 해제하면 사용자가 손으로 체크한 것까지 지운다.
 */
export function stepsToUncheck(prev: SetupKeys | undefined, next: SetupKeys): string[] {
  if (prev === undefined) return [];
  return (Object.keys(SETUP_STEP_IDS) as (keyof SetupKeys)[])
    .filter((key) => prev[key] && !next[key])
    .map((key) => SETUP_STEP_IDS[key]);
}
```

export async function scanNow(store: LensStore, onDone: () => void): Promise<void> {
