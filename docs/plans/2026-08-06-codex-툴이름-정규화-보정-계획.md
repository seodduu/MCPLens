# codex 툴 이름 정규화 보정 계획

작성일 2026-08-06 / 기점 커밋 `73318ca`

codex가 훅에 넘기는 툴 이름은 원본이 아니라 `mcp__<서버>__<툴>`로 합쳐지며 변형된 이름이다.
그 변형을 되돌리지 않고 저장해서, 같은 툴이 클라이언트마다 다른 행으로 갈라진다. 갈라진 행은
정의를 못 찾아 토큰이 `≥N` 하한값으로 표시된다. 근거가 되는 숫자가 틀리므로 고친다.

## 발견 경위와 증거

사이드바에서 `codex > notion`이 `notion_search 2 calls · ≥52 tokens`로만 뜬다는 보고에서
시작했다. 처음 세운 가설("codex가 로그에 밑줄로 찍는다")은 **틀렸다.** 실제 로그 원문에는
올바른 이름이 있다.

`~/.codex/sessions/2026/08/06/rollout-2026-08-06T00-13-04-019fd27c-….jsonl` 35행:

```json
{"timestamp":"2026-08-05T15:15:07.741Z","type":"event_msg","payload":{
  "type":"mcp_tool_call_end",
  "invocation":{"server":"notion","tool":"notion-search", ...}}}
```

같은 파일 30행, codex의 code mode가 모델에게 툴을 노출하는 형태:

```json
{"type":"custom_tool_call","name":"exec",
 "input":"const x = ALL_TOOLS.find(x=>x.name===\"mcp__notion__notion_search\");\ntext(x);\n"}
```

`mcp__<서버>__<툴>`의 구분자가 `__`이므로 툴 이름 안의 `-`가 `_`로 바뀐다. 그리고 DB에 남은
것은 변형된 쪽이다.

```
로그 원문:  15:15:07.741   invocation.tool = notion-search
DB 기록:    15:15:07.785   tool_name       = notion_search   (44ms 늦음 = 훅이 쓴 것)
```

이 저장소에서 붙임표를 쓰는 서버는 notion 하나뿐이다. 그래서 다른 서버는 이 변형이
항등변환이라 아무 증상이 없다.

```
server_name          붙임표 쓰는 툴  전체
notion               27              27
brave-search          0               8
huggingface           0               4
openaiDeveloperDocs   0               5
lenstest / lenstest2  0              24
node_repl             0               3
deepwiki / tiny       0               6
```

결과적으로 같은 툴이 DB에 두 행으로 갈라져 있다.

```
client       tool_name      호출 수
claude-code  notion-search  8
codex        notion_search  2
```

## 원인 두 곳

### (1) 호출: 되돌리는 코드가 아예 없다

`packages/codex-plugin/runtime/ingest/clients/codex/decoder.js:62`

```js
const MCP_TOOL_NAME = /^mcp__(.+?)__(.+)$/;
const toolMatch = MCP_TOOL_NAME.exec(payload.tool_name);
[, serverName, toolName] = toolMatch;
```

훅 런타임은 DB를 보지 않으므로 여기서는 되돌릴 수 없다(무엇이 원본인지 알 방법이 없다).
쪼개기까지만 하는 것은 맞다. 문제는 **core 쪽에도 되돌리는 단계가 없다는 것**이다.
`rebuildSession`(`packages/core/src/store/store.ts:823`)이 `call.toolName`을 그대로 넣는다.

### (2) 로드: 되돌리는 코드는 있는데 정확 일치라 붙임표에서 깨진다

`packages/core/src/store/store.ts:836` `attributeCodexLoadName`

```ts
.filter((row) => `mcp__${row.server_name as string}__${row.tool_name as string}` === load.toolName);
```

`mcp__notion__notion-search`와 `mcp__notion__notion_search`는 다른 문자열이므로 매칭이
실패하고 귀속이 안 된다. 설계 의도(유일하게 일치할 때만 쪼갠다)는 맞고 비교 방식만 좁다.

## 고치는 방향

**되돌리기는 문자열만 보고 할 수 없다.** `notion_search`가 `notion-search`에서 왔는지
`notion_search`에서 왔는지 이름만으로는 구분되지 않는다. 그러므로 **스캔으로 이미 알고 있는
그 서버의 정의 목록에 대조한다.**

정의 이름에 codex와 같은 변형을 걸어 비교하고, **일치가 정확히 하나일 때만** 원본으로
되돌린다. 둘 이상이면 모호하므로 손대지 않는다. 추측해서 되돌리면 틀린 조인이 생기고,
그것은 지금의 `≥N` 표시보다 나쁘다. `≥N`은 모른다고 말하지만 틀린 조인은 아는 척한다.

변형 규칙은 `[^A-Za-z0-9_]` -> `_`로 둔다. 관측된 것은 `-` 하나지만, `__` 구분자를 지키려는
치환이므로 같은 이유로 `.`이나 공백도 대상이 된다. 유일성 조건이 있으므로 넓게 잡아도
잘못 되돌아가지 않는다.

이미 저장된 행도 고친다. 로그 커서(`file_cursors`)가 이미 지나가서 재수집만으로는 복구되지
않는다. 이 저장소에는 `reattributePendingCodexLoads`라는 같은 성격의 복구 경로가 이미 있으므로
그 자리에 얹는다.

**스키마는 바꾸지 않는다.** 열도 인덱스도 그대로다. 마이그레이션 번호를 늘리지 않는다.

**구현**

공통 헬퍼. 파일 상단의 다른 모듈 스코프 함수들과 같은 위치에 둔다.

```ts
/**
 * The name codex hands to a hook is not the tool's own name. Codex joins server and tool into
 * `mcp__<server>__<tool>` and, because `__` is the separator, replaces characters that would break
 * that shape. `notion-search` therefore arrives as `notion_search`. Most servers name their tools
 * with underscores already, so the transform is the identity for them and nothing shows; a server
 * that uses dashes is the only one that splits into two rows.
 *
 * The transform cannot be inverted from the string alone (`notion_search` could have come from
 * either spelling), so the inverse is resolved against the definitions the scan already recorded.
 */
function codexSanitizeToolName(name: string): string {
  return name.replace(/[^A-Za-z0-9_]/g, '_');
}
```

`LensStore`에 private 메서드를 추가한다.

```ts
/**
 * The tool name as the scan recorded it, for a name codex already split into server and tool.
 *
 * Returns the argument unchanged unless exactly one definition of that server sanitizes to it.
 * Two or more matches are ambiguous, and guessing would produce a join that is confidently wrong;
 * leaving the name alone keeps the display at "≥N tokens", which says it does not know.
 */
private canonicalCodexToolName(serverName: string, toolName: string): string {
  const rows = this.select(
    `SELECT tool_name FROM tool_definitions WHERE server_name=?`, [serverName],
  ).map((row) => row.tool_name as string);
  if (rows.includes(toolName)) return toolName;   // already canonical: no lookup needed
  const matches = rows.filter((name) => codexSanitizeToolName(name) === toolName);
  return matches.length === 1 ? matches[0]! : toolName;
}
```

`rebuildSession`(823행)의 호출 삽입을 다음으로 바꾼다.

```ts

    ? this.canonicalCodexToolName(call.serverName, call.toolName)
    : call.toolName;

    `INSERT INTO tool_calls(session_id, server_name, tool_name, called_at, duration_ms, is_error, response_tokens)
     VALUES(?,?,?,?,?,?,?)`, [sessionId, call.serverName, toolName, call.calledAt,
      call.durationMs, Number(call.isError), call.responseTokens]);
}
```

`attributeCodexLoadName`(836행)의 후보 비교를 정확 일치에서 변형 후 비교로 바꾼다.

서버 이름에도 변형을 거는 이유: 합쳐진 이름은 서버와 툴을 한 번에 치환한 결과이므로,
서버 이름에 붙임표가 있으면(`brave-search`) 그쪽도 `_`가 된다. 한쪽만 변형하면
`brave-search`의 툴이 영원히 안 붙는다.

기존 행 복구. `reattributePendingCodexLoads`를 확장하는 대신 옆에 하나 더 둔다. 이름이
하는 일을 그대로 말하도록 남긴다.

```ts
/**
 * Rebuilds codex sessions whose stored tool name is codex's joined-form name rather than the
 * tool's own. The log cursor has already passed these files, so re-ingesting alone never reaches
 * them; the rebuild re-runs the name resolution against the definitions present now.
 */
private reattributeSanitizedCodexToolNames(): void {
  const rows = this.select(
    `SELECT DISTINCT c.session_id FROM tool_calls c
     JOIN sessions s ON s.session_id = c.session_id
     WHERE s.client = 'codex'
       AND NOT EXISTS (
         SELECT 1 FROM tool_definitions d
         WHERE d.server_name = c.server_name AND d.tool_name = c.tool_name)
       AND EXISTS (
         SELECT 1 FROM tool_definitions d WHERE d.server_name = c.server_name)`, [],
  );
  for (const row of rows) this.rebuildSession(row.session_id as string);
}
```

두 번째 `EXISTS`가 필요한 이유: 그 서버를 아직 한 번도 스캔하지 않았으면 대조할 정의가 없고,
매번 헛되이 세션을 다시 지었다 만들게 된다. 스캔된 서버에 대해서만 시도한다.

248행과 597행, `reattributePendingCodexLoads()`를 부르는 자리 **바로 뒤**에서 부른다.

- **`mcp__codex_apps__…` 형태의 로드가 서버 귀속 없이 남는 문제.** `tool_loads`에
  `server_name`이 빈 행이 있다(`(code-mode-search)` 73건 포함). 이건 codex의 내장 앱 툴이라
  MCP 서버 목록에 없어서 대조에 실패하는 것으로 보인다. 원인 조사가 더 필요하고 이 변경과
  독립적이다.
- **표시 규칙 변경.** codex 아래에 안 쓴 툴 26개가 안 보이는 것은 지연 로딩 모드의 의도된
  동작이다(`visibleMatrixRows`). 이 계획은 그것을 바꾸지 않는다.
