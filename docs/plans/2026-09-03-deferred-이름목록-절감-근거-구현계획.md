## 4. T0 공유 계약

`packages/core/src/types.ts`에 그대로 넣는다. 전량이다.

```ts
export interface ToolDefinition {
  serverName: string;
  toolName: string;
  definitionTokens: number;
  advertisedTokens: number | null;
  /**
   * What the tool costs when the client defers it: the calibrated size of its name-list stub
   * (the line the harness keeps in context so the model can ToolSearch for it). Snapshot taken
   * at scan time. null on rows scanned before the name-list estimator existed.
   */
  nameListTokens: number | null;
  estimatorVersion: EstimatorVersion;
  scannedAt: string;
  firstScannedAt: string;
}

export interface MatrixRow {
  serverName: string;
  toolName: string;
  definitionTokens: number | null;
  /** Name-list stub cost under deferred loading (ToolDefinition.nameListTokens). null when unknown. */
  nameListTokens: number | null;
  callCount: number;
  responseTokens: number;
  loadedSessionCount: number;
  sessionCount: number;
  recommendation: Recommendation;
  reliability: ReliabilityStats;
  loadPattern: LoadPattern;
}

export interface ServerVerdict {
  serverName: string;
  action: 'remove-server' | 'keep';
  confidence: RecommendationConfidence;
  evidence: ServerEvidence;
  /**
   * What removing the server measurably saves per session: definitions plus instructions under
   * upfront loading; instructions plus the name-list stubs (nameListTokens) under deferred loading.
   */
  measuredPerSessionTokens: number;
  /**
   * Deferred only: sum of nameListTokens over the server's defined tools that carry an estimate.
   * 0 under upfront loading. null when no tool of the server carries an estimate.
   */
  nameListTokens: number | null;
  /** Deferred only: defined tools whose nameListTokens is null (scanned before the estimator). 0 under upfront. */
  unmeasuredNameListEntries: number;
  reason: string;
}
```

`packages/core/src/store/schema.sql` `tool_definitions`에 `name_list_tokens INTEGER` 컬럼을
`advertised_tokens` 다음 줄에 추가한다. `store.ts` 마이그레이션은 기존 패턴 그대로다
(`PRAGMA table_info(tool_definitions)`에 `name_list_tokens`가 없으면
`ALTER TABLE tool_definitions ADD COLUMN name_list_tokens INTEGER`). `upsertDefinitions`는
컬럼을 INSERT·UPDATE 양쪽에 넣고, `allDefinitions`는
`nameListTokens: (r.name_list_tokens as number | null) ?? null`로 읽는다.

`engine.ts` `baseRow`에 `nameListTokens: null`을 넣고, 정의에서 만드는 행은
`d.nameListTokens`를 넣는다(호출·로드 전용 행은 null). `serverVerdict.ts`는 T0에서
`nameListTokens: null`을 통과시키기만 한다. 의미는 T1이 넣는다.

### 5.2 후보 규칙과 채점

툴 하나의 스텁 텍스트 `S(tool)` 후보. `N = mcp__<server>__<tool>`, `D = description ?? ''`.

| id | S |
|---|---|
| `name` | `N` |
| `name-full` | `N: D` |
| `name-line1` | `N: D의 첫 줄` |
| `name-sent1` | `N: D의 첫 문장` (`/(?<=\.)\s/` 분리 첫 조각) |
| `name-80` / `name-100` / `name-150` / `name-200` | `N: D.slice(0, k)` |
| `json` | `JSON.stringify({ name: N, description: D })` |

각 후보에 대해 `raw_server = Σ_tool countTokens(S + '\n')`(o200k_base, `tokenize.ts`)를 구하고
13서버에 대해 `measured ≈ F × raw`를 원점 통과 최소제곱으로 적합한다(`F = Σ m·r / Σ r²`).
정의 토큰 보정과 같은 모양이며 툴당 상수항은 두지 않는다(정의 보정 때 잡음 안이었다. 이번에도
상수항을 같이 적합해 절대 오차 평균이 3%p 이상 좋아질 때만 채택하고, 채택하면 상수까지 코드에
적는다).

채점: 서버별 `|F·r − m| / m`의 평균(주 지표)과 최댓값. 후보 중 평균이 가장 낮은 것을 고른다.
동률(1%p 이내)이면 더 단순한 쪽(표에서 위쪽)을 고른다. 고른 규칙으로 day-08 합계 4,021을
예측해 오차를 근거 파일에 적는다(합격선 없음, 기록만).

합격선: 평균 15% 이하. 못 넘기면 가장 좋은 규칙을 그대로 쓰고 실제 수치를 상수 주석과 근거
파일에 적는다. 이 경우에도 verdict 절감은 "unmeasured"보다 정직하므로 되돌리지 않는다.

### 6.1 claimed 계산을 모드별로 가른다

`pilot/ledger.mjs`:

```js
/** What Lens claimed arm B would save per session on the first turn, in the unit the mode
 *  actually measures: definition tokens under eager, name-list stubs (+ instructions for a
 *  whole-server removal) under deferred. */
function lensClaimedSavingsForServer(rows, verdict, deniedTools, { mode, serverVerdict = null }) {
  if (mode === 'eager') {
    if (verdict === 'off') return rows.reduce((sum, r) => sum + (r.definitionTokens || 0), 0);
    return rows.filter((r) => deniedTools.includes(r.toolName))
      .reduce((sum, r) => sum + (r.definitionTokens || 0), 0);
  }
  // deferred
  if (verdict === 'off') {
    if (serverVerdict && serverVerdict.measuredPerSessionTokens != null) return serverVerdict.measuredPerSessionTokens;
    return rows.reduce((sum, r) => sum + (r.nameListTokens || 0), 0);
  }
  return rows.filter((r) => deniedTools.includes(r.toolName))
    .reduce((sum, r) => sum + (r.nameListTokens || 0), 0);
}
```

`serverVerdict`는 `lens-<batch>-<mode>.json`의 `servers` 배열에서 이름으로 찾는다(없으면 null).

`lensEstimateTokens`(서버 레코드): eager는 기존(정의 토큰 합), deferred는
`Σ rows.nameListTokens`(하나라도 null이면 null) `+ (serverVerdict?.measuredPerSessionTokens ?? 0) − (serverVerdict?.nameListTokens ?? 0)`
즉 이름 목록 합 + instructions. `errorRate`는 `measuredTokens != null && lensEstimateTokens != null`이면
모드와 무관하게 `|estimate − measured| / measured`. deferred를 null로 강제하던 코드를 지운다.

### 6.2 로드 절감을 따로 싣는다 (deferred만)

```js
// Under deferred loading, denying a tool also stops the ToolSearch loads that pulled its
// definition into context. That is a second saving, measured in taskTokens and never on the
// first turn, so it is carried separately from the first-turn figure and never added to it.
loadTokens(run) = Σ_{t ∈ run.toolLoads} definitionTokensByFullName[t]   // 리포트 행에서 조인, 없으면 0
loadSavings.measured   = round2(mean_A(loadTokens over pairedTasks) − mean_B(loadTokens over pairedTasks))
loadSavings.lensClaimed = round2(Σ_{denied tool rows} (row.recommendation.evidence.costPerSession ?? 0))
```

off 서버는 모든 툴 행이 denied다. 모드 블록에 `loadSavings: { lensClaimed, measured }`를
`savingsErrorRate` 다음에 넣는다. eager 블록에는 넣지 않는다.
