# 리포트 가독성 재설계 — 조치 중심 리포트

> 대상 표면: `mcp-lens.showReport` (VS Code 커맨드) + `mcp-lens report --format ai` (CLI).
> 매트릭스 트리(사이드바)와 `--format table`/`json`은 이 설계의 범위 밖 — 형식 유지.

## 1. 문제 — 실출력 진단

현재 `showReport`(`packages/extension/src/extension.ts:129-148`)는 클라이언트별로
`visibleMatrixRows`를 한 줄씩 평평하게 찍는다. 실데이터(claude-code 159세션 /
codex 94세션 / gemini-cli 3세션)에서 약 200줄이 나오고, 그중 사용자가 실제로
행동에 옮길 수 있는 항목은 3개다.

| # | 증상 | 코드 근거 |
|---|---|---|
| P1 | **정렬이 조치 우선순위가 아님.** `buildMatrix`가 정의 토큰 내림차순으로 정렬해 반환하므로, "지금 지워도 되는 툴"과 "관찰이 더 필요한 툴"이 크기 순으로 뒤섞인다 | `engine.ts:100` |
| P2 | **서버 공통 근거가 툴마다 복제.** `filter-server` reason에 "서버 notion의 20툴 중 2개만 사용 — 툴 필터링 권장"이 통째로 들어가 notion 10줄이 사실상 같은 문장 | `engine.ts:170` |
| P3 | **확신 꼬리말이 줄마다 반복.** `confidencePhrase`가 "관찰 부족(N세션), 10세션 누적 시 확정. 아직 확정 권고 아님"을 각 줄 끝에 붙인다. gemini-cli 섹션은 100줄 전부가 이 꼬리를 단다 | `evidence.ts:222-234` |
| P4 | **정보량 0인 줄이 목록의 절반.** `keep (N회 호출됨)` — 조치가 필요 없다는 사실 외에 아무것도 말하지 않는데 자리는 똑같이 차지 | `engine.ts:200` |
| P5 | **합계가 없다.** `sessionSavings`가 이미 계산되는데 이 리포트에는 실리지 않아, "그래서 얼마를 아낄 수 있나"에 답할 수 없다 | `extension.ts:145` |
| P6 | **관찰량 부족한 클라이언트가 가장 시끄럽다.** gemini-cli는 3세션뿐이라 모든 권고가 `confidence: 'low'`인데, UPFRONT 모드라 `visibleMatrixRows`가 아무것도 걸러내지 않아(`engine.ts:146`) 미사용 정의 100여 개가 전부 출력된다. **신뢰도가 가장 낮은 섹션이 가장 길다** | `engine.ts:146`, `evidence.ts:212` |

P6이 이 리포트를 못 읽게 만드는 지배적 원인이다.

## 2. 설계 원칙

1. **역피라미드** — 합계 → 조치 목록 → 근거 → 원시 데이터. 첫 5줄만 읽어도 결론이 선다.
2. **조치 중심 버킷** — 정렬 기준을 "정의 토큰 크기"에서 "지금 무엇을 해야 하는가"로 바꾼다.
3. **근거는 가장 높은 공통 계층에 한 번만** — 서버 공통 근거는 서버 헤드라인에,
   확신 꼬리말은 버킷 제목에. 툴 줄에는 그 툴만의 숫자만 남긴다.
4. **확신이 낮으면 짧게** — 확신과 지면을 비례시킨다. P6의 직접적 해소.
5. **판정은 그대로, 표시만 바꾼다** — `Recommendation.action`/`confidence` 산정 로직은 손대지 않는다.
   (기존 결정사항 "확신이 낮아도 판정은 강등하지 않는다 — 표면이 후보로 렌더링한다", `engine.ts:167` 주석과 일관)

## 4. 데이터 모델

### 4-1. 공유 계약 확장 — `Recommendation.reasonParts`

산문 `reason` 문자열 하나로는 "서버 공통 근거"와 "이 툴만의 근거"를 분리할 수 없어
중복 제거가 불가능하다(P2·P3). 구조화 필드를 **추가**한다.

```ts
// packages/core/src/types.ts
/**
 * reason 산문의 구성 요소. 렌더러가 계층별로 재배치·중복 제거할 수 있게 분해해 둔다.
 * reason 문자열은 이 조각들의 결합으로 생성되며 기존 표면과 바이트 단위로 동일하다.
 */
export interface RecommendationReason {
  /** 이 툴만의 근거. 예: "정의 900토큰, 호출 0회" */
  basis: string;
  /** 서버 단위 공통 근거 — filter-server에서만 채워짐. 예: "20툴 중 2개만 사용" */
  serverBasis: string | null;
  /** 조치 효과 한 줄. 예: "제거 시 매 세션 약 900토큰 절약" | "검색 공간 정리 효과" */
  effect: string | null;
  /** 확신 꼬리말 = confidencePhrase의 산출물. 확정 권고면 null이 아니라 근거 문장이 온다 */
  caveat: string | null;
}
```

`Recommendation`에 `reasonParts: RecommendationReason`을 추가한다. **`reason: string`은 유지**하며
`engine.ts`가 parts를 결합해 생성한다 — 기존 CLI 테이블·트리 tooltip·JSON 출력이 전부 무손상.

### 4-2. 리포트 모델 (신규 `packages/core/src/report/`)

렌더링과 집계를 분리한다. 집계는 순수 함수, 렌더러는 문자열 조립만 한다.

```ts
// packages/core/src/report/model.ts
export type ReportBucket = 'act' | 'candidate' | 'inspect' | 'healthy';

export interface ReportTool {
  toolName: string;
  perSessionTokens: number | null;   // = definitionTokens
  totalObservedCost: number | null;
  callCount: number;
  errorCount: number;
  errorRate: number | null;
  responseTokens: number;
  lastCalledAt: string | null;
  /** 이 툴만의 꼬리말 (서버 공통이 아닌 것). 없으면 null */
  note: string | null;
}

/** 같은 서버 · 같은 action · 같은 confidence의 툴 묶음 = 한 번에 취하는 조치 단위 */
export interface ReportGroup {
  serverName: string;
  action: Recommendation['action'];
  confidence: RecommendationConfidence;
  /** 서버 공통 근거 (reasonParts.serverBasis). 단일 툴 그룹이면 null */
  headline: string | null;
  /** 그룹 대표 꼬리말 (reasonParts.caveat 중 최빈값) */
  caveat: string | null;
  perSessionTokens: number;          // 그룹 내 합
  totalObservedCost: number;
  tools: ReportTool[];               // perSessionTokens 내림차순
}

export interface ClientReport {
  client: ClientId;
  sessionCount: number;
  /** 관찰 부족으로 전체를 접었는가 (§4-3 규칙) */
  collapsed: boolean;
  buckets: Record<ReportBucket, ReportGroup[]>;
  /** collapsed일 때만 의미 있음 — 접힌 미사용 정의 요약 */
  collapsedSummary: { toolCount: number; perSessionTokens: number } | null;
  /** visibleMatrixRows가 숨긴 실비용 0 툴 수 */
  hiddenToolCount: number;
}

export interface ReportModel {
  generatedAt: string;
  days: number;
  clients: ClientReport[];
  totals: {
    actPerSessionTokens: number;
    candidatePerSessionTokens: number;
    actServerCount: number; actToolCount: number;
    candidateServerCount: number; candidateToolCount: number;
    inspectToolCount: number; inspectWastedTokens: number;
    healthyToolCount: number; healthyResponseTokens: number;
  };
}
```

### 4-3. 버킷 배정 규칙

| 버킷 | 조건 |
|---|---|
| `act` | `action ∈ {remove, filter-server}` **and** `confidence ∈ {high, medium}` |
| `candidate` | `action ∈ {remove, filter-server}` **and** `confidence === 'low'` |
| `inspect` | `action === 'inspect'` (확신 무관 — 실패는 그 자체로 관찰된 사실) |
| `healthy` | `action === 'keep'` |
| (제외) | `action === 'unknown'` — 정의 토큰 미확보. 클라이언트 각주로만 표기 |

**클라이언트 접기 규칙 (P6 해소):**
`buckets.act`가 비어 있고 `buckets.inspect`도 비어 있으며 `buckets.candidate`가 비어 있지
않으면 → `collapsed = true`. 이 클라이언트는 3줄 요약으로 대체한다.
"조치할 것도 점검할 것도 없는데 후보만 잔뜩"인 상태가 정확히 gemini-cli다.

### 4-4. 정렬

- 그룹: `perSessionTokens` 내림차순 (조치 효과 순)
- 버킷: `act` → `candidate` → `inspect` → `healthy` 고정
- 클라이언트: `collapsed === false`가 먼저, 그다음 `sessionCount` 내림차순

## 5. 표시 정책

**툴 목록 절단.** 그룹의 툴이 6개를 넘으면 상위 5개만 쓰고 나머지는
`그 외 N개 M tok`으로 합산한다. `<details>` 같은 HTML 접기는 쓰지 않는다 —
이 리포트는 raw 마크다운 텍스트 문서로 열리고(`extension.ts:146`),
**AI에게 통째로 붙여넣는 것이 제품의 용도**이므로 HTML 태그는 순손해다.

전체를 봐야 할 때의 탈출구:
- VS Code: `mcpLens.reportDetail: 'summary' | 'full'` (기본 `summary`)
- CLI: `mcp-lens report --format ai --full`
- 언제나: `--format json` (절단 없음, 기존 그대로)

**숫자 서식.** 1,000 이상은 천단위 구분자. 정의 토큰은 항상 "세션당"을 명시한다 —
`totalObservedCost`(누적)와 혼동되면 절감량을 100배 과대평가하게 된다.

## 6. 비목표

- 웹뷰·인터랙티브 UI — 마크다운 텍스트 문서를 유지한다(AI 전달 용도).
  정렬·필터가 필요하면 사이드바 트리와 대시보드가 이미 있다.
- `Recommendation.action` / `confidence` 산정 로직 변경 — 판정은 그대로다.
- 사이드바 트리(`matrixTree.ts`) 레이아웃 변경 — 별건.
- `--format table` 컬럼 변경 — 기계 판독용이므로 그대로 둔다.

| 위험 | 완화 |
|---|---|
| `reason` 문자열이 미묘하게 바뀌어 기존 테스트·트리 tooltip 회귀 | Wave 1 Task A에 **기존 reason 문자열 바이트 동일성 회귀 테스트**를 먼저 세운다 |
