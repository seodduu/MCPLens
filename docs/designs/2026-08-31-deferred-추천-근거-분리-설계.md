# deferred 추천의 근거를 툴과 서버로 분리한다

작성 2026-08-31. 근거는 파일럿 day-04·day-05 실측
(`docs/designs/2026-08-26-일일-배치-before-after-측정-설계.md` 12절).

## 1. 목표·비범위·완료 조건

### 목표

지연 로딩(deferred) 세션에서 Lens가 내는 추천이 **정의가 실제로 컨텍스트에 들어간 관측**에만
근거하게 만든다. 그리고 그 규칙 때문에 사라지는 "한 번도 안 쓴 서버" 판정을 서버 단위 증거로
되살린다.

1. **툴 단위 (C).** deferred에서 `remove`·`filter-server`의 후보는 **로드된 적이 있는데 호출되지
   않은 툴**이다. 등급은 로드된 세션 수로 매기고, 절감은 "세션당 정의 무게"가 아니라
   "검색에 끌려온 횟수 × 정의 무게"를 세션 수로 나눈 값으로 말한다. 로드 0인 툴은 추천 대상에서
   빼고 `unobserved`로만 표시한다.
2. **서버 단위 (B).** 서버가 설정돼 있던 세션 수를 툴 증거와 별도로 세서, 로드도 호출도 없는
   서버에 `remove-server` 판정을 낸다. deferred에서도 서버의 이름 목록은 매 세션 컨텍스트에
   있으므로 이 관측은 세션 전부를 셀 자격이 있다.

### 비범위

- 이름 목록 항목의 토큰 추정기. deferred에서 서버 하나가 차지하는 이름 목록 비용은 아직 재지
  않는다. 서버 절감에서 그 부분은 `unmeasuredNameListEntries`로 개수만 남긴다.
- 확장(VS Code)에서 `remove-server`를 한 번에 적용하는 UI. 판정을 리포트·JSON에 싣는 데까지다.
- eager 판정 변경. UPFRONT 세션의 규칙은 그대로다.
- 툴 설명 문구 개선 제안("설명이 `search_books`와 겹친다"). 이번 판은 오염원을 `remove`로 잡는
  데까지고, 원인 진단은 후속이다.

### 완료 조건

- deferred 세션 10개, 툴 A 로드 3·호출 0, 툴 B 로드 0·호출 0일 때 A는 `remove`(등급은 3세션
  기준 `low`), B는 `unobserved`다. 두 툴이 같은 서버면 서버는 `keep`이다.
- deferred 세션 10개, 서버 S의 툴 전부 로드 0·호출 0, S가 그 클라이언트에 설정돼 있음. 서버 판정은
  `remove-server`이고 등급은 `configuredSessions=10`, `observedDays`에 따른다.
- day-05 deferred 관측 홈(`pilot/.work/lenshome-deferred`)으로 리포트를 다시 만들면 `remove`·
  `filter-server` 행이 로드 0인 툴에 하나도 붙지 않고, `openlibrary_get_work`,
  `openlibrary_get_editions`, `musicbrainz_get_artist`는 `remove` 또는 `filter-server`로 남는다.
- `npm test`와 core·cli·extension `tsc --noEmit -p`가 녹색.

## 2. 전제와 판단 근거

### day-05가 보여준 것

deferred 천장 팔(floor `low`)이 43툴을 껐는데 첫 턴 컨텍스트는 808토큰만 줄었고 rare 성공은
10/10에서 1/10로 떨어졌다. 끈 43툴은 거의 전부 **로드 0**이었고, 검색에 끌려왔지만 안 불린 툴
3개(`openlibrary_get_work`, `openlibrary_get_editions`, `musicbrainz_get_artist`)는 관측에서
로드됐다는 이유로 살아남아 팔 B에서도 pollution 8건이 그대로였다. 깎아야 할 3개를 남기고 깎을
필요 없는 43개를 깎은 것이다.

### deferred에서 툴 하나의 비용은 어디에 있나

| 상태 | 컨텍스트에 있는 것 | 세션당 비용 | "안 썼다"가 증거인가 |
|---|---|---|---|
| 로드 0 | 이름 한 줄 | 약 50토큰 | 아니오. 정의를 본 적이 없다 |
| 로드됐고 호출 0 | 정의 전문 (검색마다) | 정의 무게 × 끌려온 횟수 | 예. 보고도 안 썼고 매번 다시 끌려온다 |

그러므로 deferred 툴 추천의 대상은 둘째 줄이고, 등급은 끌려온 세션 수로 매긴다. 첫째 줄은
비용도 근거도 없으니 추천하지 않는다. 2026-08-30에 넣은 관측 게이트(`6894218`, deferred 세션은
그 툴의 로드가 있을 때만 관측 세션으로 센다)가 이미 `observedSessions`를 이 정의로 바꿔 놓았다.
이번 판은 그 위에서 action과 절감 문구를 맞춘다.

### 서버는 왜 따로 세나

관측 게이트의 부작용이다. 서버 S의 툴 12개가 전부 로드 0이면 툴 증거의 합으로는 S도 "관측 0"이
되어 `low`에 묶인다. 그런데 deferred에서도 S의 이름 목록 12줄은 매 세션 컨텍스트에 있었다.
모델은 한 달 내내 그 이름을 보고 한 번도 검색하지 않았다. 이것은 "S는 필요 없다"의 완전한
증거이고, 세션 전부를 셀 자격이 있다. 툴과 서버는 관측 조건이 다르므로 증거도 따로 둔다.

eager에서는 정의가 매 세션 들어가므로 툴 증거만으로 이미 서버 `off`가 나온다. 서버 증거는
deferred를 위한 보완이지만 모드와 무관하게 같은 규칙으로 계산한다. 규칙이 갈리면 리포트가
모드마다 다른 말을 하게 된다.

### 왜 서버 제거는 로드가 하나라도 있으면 안 되나

로드됐지만 안 불린 툴은 C의 영역(툴 `remove`)이다. 서버 제거는 regret이 가장 낮아야 하는
추천이므로 "로드 0·호출 0"만 자격이 있다. 로드가 있는 서버는 툴 단위로 깎고 서버는 남긴다.

## 3. 판정 규칙

### 3.1 툴 단위 (`recommend`, deferred 지배 모드)

지배 모드가 `DEFERRED_MEASURABLE` 또는 `DEFERRED_ESTIMATED`일 때, `callCount === 0`이고
`definitionTokens != null`인 행에 대해:

| 조건 | action | confidence | evidence 해석 |
|---|---|---|---|
| `evidence.observedSessions === 0` | `unobserved` | `low` | 관측 없음. 정의가 컨텍스트에 들어간 세션이 하나도 없다 |
| `observedSessions > 0`, 서버 필터 조건 충족 | `filter-server` | `removeConfidence(evidence)` | `observedSessions` = 정의가 컨텍스트에 있던 창 안 세션 수 |
| `observedSessions > 0`, 그 밖 | `remove` | `removeConfidence(evidence)` | 같음 |

조건이 로드 수가 아니라 `observedSessions`인 이유는 창에 UPFRONT 세션이 섞일 수 있기
때문이다. UPFRONT 세션은 정의를 통째로 보냈으므로 로드 기록이 없어도 관측이다. 순수 deferred
창에서는 `observedSessions`가 곧 로드된 세션 수이므로 결과가 같다.

서버 필터 조건은 기존 그대로다(`server.total >= 10 && server.used > 0 && used/total < 0.2`).

`DEFERRED_OPAQUE`가 지배 모드면 기존대로 `evidenceLabel: 'not measurable'`이며, 이 규칙에서
로드 0인 행은 역시 `unobserved`다(OPAQUE 세션은 관측으로 세지 않으므로 로드가 있어도 관측 0일
수 있다. 그때는 `observedSessions=0`이라 `remove/low`가 되며 그대로 둔다. OPAQUE는 어차피
바닥선을 못 넘는다).

UPFRONT 지배 모드는 변경 없음.

### 3.2 절감 수치 (deferred)

`RecommendationEvidence`에 `windowSessions`를 추가한다. 창 안 세션 수이며 모드 게이트를 거치기
**전**의 수다(정의가 들어갔든 아니든 그 툴이 존재하던 세션 수).

- `totalObservedCost = definitionTokens × observedSessions` (기존 식. deferred에서
  `observedSessions`가 로드 세션 수이므로 "정의가 실제로 들어간 총량"이 된다)
- `costPerSession`
  - UPFRONT: `definitionTokens` (기존)
  - deferred: `windowSessions > 0 ? round(definitionTokens × observedSessions / windowSessions) : null`

effect 문구(deferred, `remove`·`filter-server`):

```
in context in {observedSessions} of {windowSessions} sessions ({loadedSessionCount} pulled in by search), about {definitionTokens} tokens each time. Removing saves about {costPerSession} tokens per session and cleans up the search space
```

`unobserved`의 basis: `never loaded in {windowSessions} sessions under deferred loading, so there is no evidence yet`. effect·caveat는 null.

### 3.3 서버 단위 (`buildServerVerdicts`)

대상 서버 = 정의가 하나 이상 있는 서버. 서버마다:

- **창 시작** = `min(그 서버 툴들의 firstScannedAt 최소, 그 서버의 첫 활동 세션 startedAt)`.
  툴 창과 같은 규칙이다.
- **설정된 세션** = `serversByClient`가 있고 비어 있지 않으면 그 세션의 클라이언트 집합에 서버가
  있는 세션, 아니면 모든 세션(레거시. 스캔 전 DB).
- **모드 게이트** = `DEFERRED_OPAQUE`는 세지 않는다. UPFRONT와 DEFERRED_*는 센다(정의 또는
  이름 목록이 있었다).
- `configuredSessions`, `datedConfiguredSessions`, `observedDays`는 툴 증거와 같은 방식으로
  센다(startedAt null은 세되 dated에는 안 넣는다).
- `loadedSessions` = 창 안에서 그 서버 툴의 로드가 하나라도 있는 세션 수.
  `calledSessions` = 호출이 하나라도 있는 세션 수.
- `lastActivityAt` = 그 서버의 모든 툴에 대해 `max(창 안 호출 시각, 창 안 로드 세션 시각,
  lastCallByTool의 전체 기간 값)`. 없으면 null.

판정:

```
remove-server  iff loadedSessions === 0 && calledSessions === 0 && lastActivityAt == null
keep           otherwise (confidence 'high')
```

`remove-server`의 등급은 `serverRemoveConfidence`:

```
configuredSessions < 5                       → low
observedDays == null || observedDays < 3     → low
configuredSessions >= 10
  && datedConfiguredSessions >= 10
  && observedDays >= 7                       → high
그 밖                                        → medium
```

툴 `removeConfidence`와 같은 임계값이다. `lastCalledAt == null` 조건은 판정 자체에 들어 있으므로
등급에서는 다시 보지 않는다.

절감:

- `measuredPerSessionTokens` = UPFRONT 지배 모드면 `Σ definitionTokens + instructionsTokens`,
  deferred면 `instructionsTokens`만.
- `unmeasuredNameListEntries` = deferred면 그 서버의 툴 수, UPFRONT면 0.

reason:

```
remove-server: never loaded or called in {configuredSessions} sessions/{observedDays}d. Removing saves about {measuredPerSessionTokens} tokens per session[ plus {n} name-list entries (unmeasured)]
keep:          called in {calledSessions} sessions   (calledSessions > 0)
               loaded in {loadedSessions} sessions, never called   (calledSessions == 0, loadedSessions > 0)
               last active {lastActivityAt:YYYY-MM-DD}, before the window   (창 안 활동이 없고 lastActivityAt만 있는 경우)
```

## 4. 공유 계약

`packages/core/src/types.ts`에 추가·변경한다. 전량이다.

```ts
export interface Recommendation {
  action: 'remove' | 'filter-server' | 'keep' | 'unknown' | 'inspect' | 'unobserved';
  // 나머지 필드 변경 없음
}

export interface RecommendationEvidence {
  observedSessions: number;
  datedObservedSessions: number;
  /**
   * Sessions inside the window before the mode gate: every session in which this tool existed,
   * whether or not its definition reached the model. Under deferred loading this is the divisor
   * that turns "pulled in N times" into a per-session figure. 0 when there is no window.
   */
  windowSessions: number;
  observedDays: number | null;
  lastCalledAt: string | null;
  /**
   * Tokens charged per session. Upfront: definitionTokens. Deferred: definitionTokens amortised
   * over the window (definitionTokens x observedSessions / windowSessions), because the definition
   * only enters context in the sessions that loaded it. null when unavailable.
   */
  costPerSession: number | null;
  totalObservedCost: number | null;
}

/** Observation evidence for one server, counted on the server's own terms (see design 2026-08-31 §3.3). */
export interface ServerEvidence {
  /** Sessions inside the window in which the server was configured (OPAQUE sessions excluded). */
  configuredSessions: number;
  /** Of those, sessions with a valid startedAt confirmed inside the window. */
  datedConfiguredSessions: number;
  /** Sessions with at least one load of any tool of this server. */
  loadedSessions: number;
  /** Sessions with at least one call of any tool of this server. */
  calledSessions: number;
  observedDays: number | null;
  /** Latest call or load of any tool of this server, all-time. null when there is none. */
  lastActivityAt: string | null;
}

export interface ServerVerdict {
  serverName: string;
  action: 'remove-server' | 'keep';
  confidence: RecommendationConfidence;
  evidence: ServerEvidence;
  /**
   * What removing the server measurably saves per session: the sum of its definition tokens plus
   * its instructions overhead under upfront loading; the instructions overhead alone under
   * deferred loading, where definitions are not in context.
   */
  measuredPerSessionTokens: number;
  /** Deferred only: name-list entries that go away with the server but have no token estimate yet. 0 under upfront. */
  unmeasuredNameListEntries: number;
  reason: string;
}
```

`EMPTY_EVIDENCE`(evidence.ts)에 `windowSessions: 0`을 넣는다.

`Recommendation.action`에 `unobserved`가 늘어나므로 action을 키로 쓰는 `Record` 상수가 깨진다.
확인된 곳: `packages/extension/src/lensTreeProvider.ts:6`(아이콘 맵),
`packages/dashboard/src/app/MatrixTable.tsx:6,14`(색·아이콘 맵). 각각 `unobserved` 키를 추가한다
(아이콘 `eye-closed`, 색 `#9a9a9a`).

## 6. 알고 시작하는 한계

- 이름 목록 추정기 도입(2026-09-03 계획). 남은 한계: 구 DB 행은 `unmeasuredNameListEntries`로
  남는다.
- `serversByClient`가 없는 DB(스캔 전)에서는 모든 세션을 설정된 세션으로 센다. 툴 증거의
  기존 레거시 규칙과 같은 완화다.
- 로드 이벤트의 `serverName`이 null이면(조인 실패) 그 로드는 서버에도 툴에도 안 붙는다. 그런
  환경에서는 `loadedSessions`가 과소가 되어 `remove-server`가 과감해질 수 있다. 관측 게이트와
  같은 한계이며, 조인 실패율은 `parseErrors`로 따로 본다.
- search-pollution의 원인(설명 중복)은 진단하지 않는다.
