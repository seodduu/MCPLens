# 사실 제시 리포트 설계

결정 근거: `docs/decisions/2026-09-12-판정-폐지와-사실-제시.md`.
이 문서는 그 결정을 제품의 자료구조와 화면으로 옮긴 것이며, 표시 계층의 유일한 진실이다.
도메인·수집 규약은 `MCP-Lens-설계문서-v2.md`가 계속 진실이다.

## 1. 목표·비범위·완료 조건

### 목표

Lens가 툴을 끄라고 말하지 않고, 사용자가 스스로 결정할 수 있는 **사실**을 준다. 사용자가
화면 하나를 보고 아래 세 질문에 답할 수 있으면 이 설계는 성공이다.

1. 이 툴을 끄면 세션당 몇 토큰이 빠지나?
2. 내가 이 툴을 얼마나, 언제 마지막으로 썼나? 그 판단은 며칠치 관측에 근거하나?
3. 이 툴을 끄면 무엇이 같이 못 쓰게 되나?

### 비범위

- 재필요 확률 산출. 결정 문서 2절이 근거를 부정했다.
- 자동 적용. 사용자가 명시적으로 토글할 때만 설정이 바뀐다.
- 수집·저장·토큰 산출 변경. 이 설계는 조회 시점 계산과 표시만 바꾼다.
- 프록시 MCP 서버, 소프트 deny, 카탈로그 툴. 별도 설계로 다룬다.

### 완료 조건

1. `packages/core`의 공개 API에 `Recommendation`·`ServerVerdict`·`RecommendationConfidence`가
   없다. `action`·`confidence`를 내보내는 경로가 하나도 남지 않았다.
2. CLI 리포트, 확장 트리뷰, 대시보드가 모두 아래 3절의 사실만 표시한다.
3. 어느 화면에서도 정렬 기준이 화면에 표기돼 있고, 사용자가 바꿀 수 있다.
4. 정렬 기준이 단일 측정값이다. 여러 사실을 가중합한 점수가 코드에 없다.
5. `npm test`가 전량 통과하고, 패키지별 `tsc --noEmit -p`가 통과한다.

## 2. 무엇이 사실인가

표시해도 되는 값의 기준은 하나다. **틀릴 수 있으면 사실이 아니다.** 측정값이거나, 원본 로그에서
직접 센 값이거나, 사용자 설정에서 읽은 값만 사실이다. 추정한 값은 추정이라고 적고 오차를 함께
적을 때만 보여준다.

| 값 | 종류 | 근거 |
|---|---|---|
| `perSessionTokens` | 측정 | eager는 정의 토큰 실측. deferred는 이름 목록 스텁 |
| `callCount`, `lastCalledAt` | 사실 | 원본 로그에서 센 값 |
| `observedSessions`, `observedDays` | 사실 | 관측 창에서 센 값 |
| `loadedNotCalledCount` | 사실 | deferred에서 로드 기록과 호출 기록의 차 |
| `errorCount`, `errorRate` | 사실 | 호출 결과에서 센 값 |
| `dependents` | 사실 | 정적 의존 분석 결과 |
| `nameListTokens` | **추정** | 오차 평균 285%. 3.4절의 표기 규칙을 따른다 |

## 3. 자료구조

### 3.1 `ToolFacts` (`Recommendation`을 대체한다)

`types.ts`의 `Recommendation`, `RecommendationReason`, `RecommendationConfidence`,
`ServerVerdict`를 지우고 아래를 넣는다. `RecommendationEvidence`는 이름만 `ObservationFacts`로
바꾸고 필드를 유지한다. 그 필드들은 전부 사실이기 때문이다.

```ts
/** 한 툴에 대해 관측으로 확정된 사실. 판단이나 등급을 담지 않는다. */
export interface ToolFacts {
  /** 이 툴을 끄면 세션당 빠지는 토큰. 스캐너가 덮지 않은 툴은 null. */
  perSessionTokens: number | null;
  /**
   * perSessionTokens 가 어떻게 나온 값인지. 화면은 이 값에 따라 표기를 바꾼다(3.4절).
   * 'measured'  : 정의 토큰 실측 (eager)
   * 'estimated' : 이름 목록 스텁 추정 (deferred). 오차를 함께 표시한다
   * 'unknown'   : 스캐너가 덮지 않았다. 수치를 표시하지 않는다
   */
  basis: 'measured' | 'estimated' | 'unknown';
  observation: ObservationFacts;
  /** deferred 에서 정의가 로드됐지만 호출되지 않은 세션 수. upfront 는 0. */
  loadedNotCalledSessions: number;
  /** 이 툴을 끄면 같이 못 쓰게 되는 같은 서버의 툴 이름. 없으면 빈 배열. */
  dependents: readonly string[];
}
```

### 3.2 `ServerFacts` (`ServerVerdict`를 대체한다)

```ts
/** 한 서버에 대해 관측으로 확정된 사실. action 도 confidence 도 없다. */
export interface ServerFacts {
  serverName: string;
  /** 서버를 통째로 끄면 세션당 빠지는 토큰. 정의·스텁 합계에 instructions 를 더한 값. */
  perSessionTokens: number;
  /** 그중 instructions 몫. 툴만 필터링하면 이 몫은 남는다. */
  instructionsTokens: number;
  /** 정의된 툴 수와 그중 관측 창 안에서 한 번이라도 호출된 툴 수. */
  toolCount: number;
  calledToolCount: number;
  observation: ServerObservationFacts;
  /** 이름 목록 스텁 추정이 없는 툴 수. 0 이 아니면 perSessionTokens 가 과소집계다. */
  unmeasuredNameListEntries: number;
}
```

`ServerObservationFacts`는 지금의 `ServerEvidence`를 이름만 바꾼 것이다. 필드를 유지한다.

### 3.3 리포트 모델

`ReportBucket`(`act`/`candidate`/`inspect`/`healthy`)을 지운다. 버킷 이름 자체가 행동 지시다.
대신 **서버 단위 묶음 하나**만 둔다.

```ts
export interface ReportServerSection {
  serverName: string;
  facts: ServerFacts;
  /** 현재 정렬 기준으로 정렬된 툴 행. */
  tools: ReportToolRow[];
}

export interface ReportToolRow {
  toolName: string;
  facts: ToolFacts;
  /** 사용자가 이미 끈 툴인지. 끈 툴도 목록에 남아야 되살릴 수 있다. */
  disabled: boolean;
}
```

`ReportGroup`의 `headline`, `caveat`, `action`, `confidence`는 전부 사라진다. `savingTokens`와
`retainedInstructionsTokens`는 `ServerFacts`로 옮겨 계산식을 유지한다. 그 둘은 판단이 아니라
"서버를 끄는 것과 툴만 끄는 것의 절감 차이"라는 사실이기 때문이다.

### 3.4 추정값 표기 규칙

`basis`가 `'estimated'`인 값은 **단독 숫자로 표시하지 않는다.** 반드시 추정임을 밝히고 현재
오차를 함께 적는다.

```
정확:   ~480 tokens (estimated, +-285% error)
금지:   480 tokens
```

`basis`가 `'unknown'`이면 숫자 자리에 `unmeasured`를 적고 0으로 채우지 않는다. 합계에서도
제외하며, 제외된 툴 수를 각주로 적는다.

이 규칙이 이 설계에서 가장 중요하다. 판정을 걷어낸 제품의 신뢰는 숫자의 정직함에만 기대기
때문이다. 이름 목록 추정기의 오차가 한 자릿수로 내려오기 전까지 deferred 수치는 이 표기를
유지한다.

## 4. 정렬

### 4.1 정렬은 판정이다

맨 위 항목이 곧 추천이다. 그래서 정렬 기준은 아래 셋 중 하나여야 하고, 전부 **단일 측정값**이다.

| 기준 | 값 | 기본값 |
|---|---|---|
| `savings` | `perSessionTokens` 내림차순 | 기본 |
| `idle` | `lastCalledAt`이 오래된 순. 호출 기록 없음이 맨 위 | |
| `calls` | `callCount` 오름차순 | |

여러 사실을 곱하거나 더한 점수를 만들지 않는다. `perSessionTokens × (1 - p)` 같은 식이 코드에
있으면 이 설계 위반이다.

### 4.2 기준을 화면에 적는다

모든 화면이 현재 정렬 기준을 문자열로 표시한다. CLI는 헤더 한 줄, 확장과 대시보드는 선택
컨트롤이다. 기본값이 `savings`인 이유(가장 큰 절감부터 검토할 수 있게)를 문서에 적고 화면에는
적지 않는다. 화면에 이유를 적으면 그것이 권고가 된다.

## 5. 화면

### 5.1 CLI 리포트

버킷 제목(`### ✅ Act now`, `### ⏳ Needs more observation`)을 전부 없앤다. 서버별 절 하나에
툴 표 하나다.

```
## claude-code · 42 sessions · sorted by savings

### notion · 3,240 tokens/session · 20 tools, 2 called

| tool | tokens/session | calls | last called | observed |
|---|---|---|---|---|
| create-page | 410 | 0 | never | 42 sessions / 14d |
| update-page | 380 | 0 | never | 42 sessions / 14d |
| search      | 350 | 31 | 2026-09-11 | 42 sessions / 14d |

18 of 20 tools were never called in this window.
Turning off the whole server saves 3,240 tokens/session (2,900 definitions + 340 instructions).
```

마지막 두 줄이 이 리포트의 핵심이다. 둘 다 센 값이고 어떤 판단도 들어 있지 않다.

### 5.2 확장 트리뷰

노드마다 사실만 붙인다. 지금의 판정 배지(`off`/`keep` 아이콘, 확신도 색)를 제거하고, 툴 행의
설명에 `토큰/세션 · 호출 수 · 마지막 호출`을 적는다. 토글은 그대로 둔다.

끈 툴은 목록에서 사라지지 않고 `disabled` 표시로 남는다. 되살리기가 한 번에 돼야 사용자가
진 리스크가 작아진다.

### 5.3 대시보드

행렬 표의 셀 색을 판정 색에서 **절감 토큰 크기**의 단계로 바꾼다. 색이 "끄세요"가 아니라
"여기가 무겁다"를 뜻하게 된다. 범례에 그 뜻을 적는다.

한글 본문이 들어가는 화면은 `word-break: keep-all`과 한글에 맞춘 자간·행간을 적용한다.

## 6. 무엇을 지우나

| 파일 | 무엇 |
|---|---|
| `packages/core/src/types.ts` | `Recommendation`, `RecommendationReason`, `RecommendationConfidence`, `ServerVerdict`, `ServerEvidence`(개명), `RecommendationEvidence`(개명) |
| `packages/core/src/engine/serverVerdict.ts` | 파일 전체. `serverFacts.ts`로 대체 |
| `packages/core/src/engine/engine.ts` | 판정 분기와 `action` 산출. 사실 조립만 남긴다 |
| `packages/core/src/engine/format.ts` | 판정 문구 생성 |
| `packages/core/src/engine/healthGate.ts` | 확신도 승격 게이트 중 판정에 걸린 부분 |
| `packages/core/src/report/model.ts` | `ReportBucket`, `ReportGroup.action/confidence/headline/caveat` |
| `packages/core/src/report/markdown.ts` | 버킷 렌더러 전부 |
| `packages/core/src/report/rollup.ts` | 버킷 분류 |

`schema.sql`은 건드리지 않는다. 판정은 저장되지 않고 조회 시점에 계산되므로 **마이그레이션이
없다.** 이것이 이 변경을 안전하게 만드는 가장 큰 사실이다.

## 7. 호환성

`packages/core`의 공개 API가 깨진다. 이 저장소 안의 소비자는 `extension`·`cli`·`dashboard`
셋뿐이고 같은 커밋에서 함께 고친다. 외부 소비자는 아직 없다.

이미 만들어진 리포트 JSON 파일(파일럿 장부의 `lens-*.json`)은 옛 스키마를 그대로 갖고 있다.
`pilot/ledger.mjs`는 그 파일들을 읽어 과거 배치를 재빌드하므로 **파일럿 스크립트는 옛 필드를
계속 읽을 수 있어야 한다.** 파일럿 코드는 이 변경의 범위가 아니며, 새 배치부터 새 스키마를
읽도록 별도 태스크에서 고친다.

## 8. 자체 검토

- 결정 문서가 부정한 두 항(재필요 확률, 후회비용)이 이 설계의 어떤 자료구조에도 없다.
- 표시하는 값이 전부 2절 표에 근거를 갖는다. 근거가 추정인 값은 하나뿐이고 3.4절이 표기를
  강제한다.
- 정렬이 판정으로 되돌아가는 경로를 4.1절이 막는다. 합성 점수 금지가 완료 조건 4번이다.
- 스키마 변경이 없어 마이그레이션 번호 역전 사고가 발생할 수 없다.
- 끈 툴이 목록에 남으므로 사용자가 진 리스크를 되돌리는 비용이 작다.
