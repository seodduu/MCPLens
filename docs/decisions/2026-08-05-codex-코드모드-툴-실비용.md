# 결정: codex 코드모드에서 검색되지 않은 툴은 표시하지 않는다

- 일자: 2026-08-05
- 상태: 확정
- 관련: `docs/reports/2026-08-05-codex-load-귀속-보정/보고서.md`, `docs/BACKLOG.md` V1

## 질문

Claude Code는 한 번도 호출되지 않은 툴도 트리에 뜬다. Codex는 안 뜬다. 이건 고쳐야 할
결함인가, 아니면 맞는 동작인가.

표시 필터는 `packages/core/src/engine/engine.ts`의 `visibleMatrixRows`이고, 지연 로딩
클라이언트에서 `callCount > 0 || loadedSessionCount > 0`인 행만 남긴다. 주석은 그 이유를
"호출 0 && 로드 0 툴은 실비용 0"이라고 적어 뒀다. 그 전제가 codex 코드모드에서도 참인지가
질문의 전부다.

## 측정

codex 코드모드 세션에서 MCP 서버 하나(툴 12개)를 등록하기 전후로 첫 턴 입력 토큰을 비교했다.

| | 세션 | codex 서버 수 | `input` | `cached` |
|---|---|---|---|---|
| A | `019fcd83` (01:02:36) | 3 | 16,039 | 9,984 |
| B | `019fcd84` (01:04:14) | 4 (`lenstest2` 12툴 추가) | 16,039 | 9,984 |

`~/.codex/config.toml` 수정 시각은 01:04:03으로 두 세션 사이에 정확히 들어간다. 서버 파일이
실재해 기동 실패도 아니다. 같은 날 다른 세션들이 16,050·16,051로 흔들리는 것에 비하면, 툴 12개를
추가하고도 **1토큰도 움직이지 않았다.** 노이즈 폭보다도 작다.

수치는 각 세션 rollout 로그의 첫 `token_count` 레코드
(`payload.info.last_token_usage`)에서 읽었다.

## 결정

**per_tool = 0. 검색되지 않은 codex 툴은 컨텍스트 비용이 없다.**

코드모드는 툴 인벤토리를 프롬프트에 넣지 않는다. 모델이 `ALL_TOOLS`를 검색할 때만 그 툴의
정의를 지불한다. 따라서 한 번도 검색되지 않은 툴은 실비용 0이고, 꺼도 절감이 0이다.

절감 0인 대상에 "Disable Globally"를 권하는 것은 근거 없는 권고이므로,
`visibleMatrixRows`가 그런 행을 숨기는 현행 동작이 **맞다.** 필터 조건은 바꾸지 않는다.

## 이 결정이 바꾼 것

원래 4차 E2E 보고서는 "Codex zero-call 액션 후보 노출 불가"를 제품 결함 후보로 기록했다.
이 측정으로 그 항목은 절반이 결함이 아님이 확정됐고, 남은 절반(검색되어 실제로 비용을 지불한
툴조차 안 보이던 것)만 진짜 결함으로 좁혀져 2026-08-05에 해결됐다.

즉 이 문서가 없으면 "codex에서 툴이 안 보인다"를 다시 결함으로 착각해 같은 조사를 반복하게
된다. 다음에 같은 의문이 들면 여기부터 읽어라.

## 재측정 방법

전제가 바뀌었는지 의심스러우면(codex 버전 업으로 인벤토리를 프롬프트에 넣기 시작했다든지)
같은 절차를 반복하면 된다.

1. `~/.codex/config.toml`을 백업한다.
2. codex 세션을 열어 `hi`만 입력하고 답이 오면 종료한다.
3. 최신 rollout 로그의 첫 `token_count`에서 `input_tokens - cached_input_tokens`를 읽는다.
4. 툴 개수를 아는 MCP 서버를 하나 등록하고 2·3을 반복한다.
5. `(B - A) / 추가된_툴_개수`가 0에 가까우면 이 결정이 여전히 유효하다.

캐시가 낀 경우 A와 B의 `cached`가 크게 다르면 델타가 오염되므로 각각 한 번 더 재서 캐시 상태를
맞춘다. 측정 사이에 다른 codex 세션을 띄우지 않는다.
