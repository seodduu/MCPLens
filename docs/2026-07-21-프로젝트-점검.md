- **Hook 우선 수집(H0~H12)** 완성·병합: inbox→coordinator→observation→정준화(native ID당 1호출)→수집 건강도→권고 게이트. 576 tests green.

- 3표면(core/CLI/extension) 분리 원칙 유지(core에 `vscode` 없음, 공유 DB 경로, WASM SQLite, 무네이티브·무신규 의존성).
- 비용축(설정 3사 발견·http/OAuth 스캔), 사용축(로그 백필+실시간), 권고 엔진, 리포트 가독성 완료.

## A. Hook 파이프라인 — 보완 (기능 갭)

### A1. Inbox drain이 확장 activate 시 1회뿐 (실행 중 훅 기여·건강도 신선도 지연) **[Med]**
> **범위 정정 (확장-only 배포):** 배포는 VS Code 확장으로만 한다. CLI-only 사용자가 없으므로 "CLI엔 drain이 없다"는 갭은 **해당 없음**(제안에서 CLI `hooks drain` 부분 삭제). 아래는 확장-only에서도 남는 부분만.
- **현상**: `extension.ts`가 activate에서 `coordinator.drainInbox()`를 **1회만** 호출한다(inbox 전용 워처·주기 drain 없음). VS Code를 켜둔 채 코딩하는 동안 발화한 훅 봉투는 **재시작 전까지 inbox에 적체**된다.
- **완화 요소**: MCP 호출은 클라이언트 **transcript 로그**에도 기록되고, 확장의 **로그 워처(chokidar)** 가 이를 실시간 반영한다 → **호출 카운트(사용축)는 훅 drain 없이도 실시간**. 훅 봉투 적체가 호출 통째 누락을 의미하진 않는다.
- **그래도 지연되는 것**: ①**수집 건강도**(healthy/hook-only/degraded는 훅+로그 관측을 둘 다 봐야 산출 — 훅 미반영이면 재시작까지 낡은 값) ②**hook-only 호출**(transcript가 깨지거나 로그에 안 남는 호출은 훅 봉투에만 존재) ③native-ID 상관·정밀 타이밍 보강 지연.
- **제안**: 확장에 `~/.mcplens/inbox/pending` chokidar 워처 추가 → 봉투 도착 즉시 drain(작은 변경). "상시 수집" 제품 성격상 건강도 신선도를 위해 권장.

### A2. Codex·Gemini 실기기 스모크 미완 (BLOCKED) **[High]**
- Claude Code만 실발화·자동설치·정준화까지 실증. Codex는 `/hooks` 해시 신뢰, Gemini는 CLI 재시작이 필요해 `docs/SMOKE.md`에 절차만 남고 `BLOCKED`.
- **제안**: 사용자 신뢰 승인 가능 시점에 Codex/Gemini도 동일 절차(설치→발화→정준 카운트→로그손상 전이) 실기기 완주.

### A3. Codex·Gemini 훅 자동 설치 미구현 **[Med]**
- 확장 자동 설치는 Claude 전용(`hookInstall.ts`/`claudeCli.ts`). Codex(`codex plugin marketplace add`+`codex plugin add`+`/hooks` 신뢰), Gemini(`gemini extensions install`+재시작)도 같은 패턴으로 확장 가능(이번 세션에 두 CLI의 마켓플레이스 방식 실검증됨).
- **주의**: Codex 신뢰 승인은 보안 게이트라 자동화 불가 → 설치 후 "/hooks에서 신뢰하세요" 안내 필요.

### A4. 롤아웃 플래그가 test-scoped only **[Med]**
- `shadow`/`count-primary`/`health-gated`는 E2E 테스트에만 존재(`hook-pipeline.test.ts`). 제품 코드에는 게이팅이 없어 실제로는 항상 훅이 정준 호출에 반영된다. 릴리스 기본값 `shadow`(로그 전용과 동일 권고)를 실제로 강제하려면 core에 롤아웃 상태 + 권고 입력 선택 로직 구현 필요.

### A5. 번들 업데이트 자가치유 안 됨 **[Low]**
- 설계는 activate마다 번들이 더 최신이면 안정 경로 재sync한다고 했으나, `detectClaudeHookInstall`이 'installed'에서 단락되어 `copyDir`에 도달하지 않는다 → 확장 업데이트로 플러그인이 바뀌어도 재설치 없이는 갱신 안 됨.
- **제안**: 설치본 version과 번들 version 비교 후 다르면 재sync(`claude plugin update` 또는 재copy+install).

## B. 감지/CLI 일관성 — 개선

### B1. CLI `hooks status` 캐시-glob이 마켓플레이스 무관 매치 **[Med]**
- 확장은 `claude plugin list --json`(권위)로 감지하지만, CLI `hooks-status.ts`는 `~/.<client>/plugins/cache/*/mcp-lens/*/`를 **broad glob**으로만 본다. 다른 마켓플레이스의 mcp-lens 캐시나 uninstall 후 잔존 캐시에 **false-positive** 가능(이번 세션에 확장 쪽에서 동일 버그를 잡아 `plugin list` 우선으로 고쳤으나 CLI는 미반영).
- **제안**: 공유 리졸버를 `@mcp-lens/core`로 추출해 CLI·확장이 동일 로직 사용, 또는 CLI도 `plugin list --json`을 우선.

### B2. `uninstallClaudeHooks` stderr 매칭 누락 **[Low]**
- 이미 제거된 플러그인 uninstall 시 claude가 `"...not found in installed plugins"`를 반환하는데, 코드의 `/not installed|no such/i`에 안 걸려 `failed`로 보고된다. 정규식에 `not found` 추가로 멱등 처리.

## C. 확장 UX/품질 — 개선

### C1. `hooksPause` 명령이 사실상 no-op **[Med]**
- `coordinator.pause`가 없어 명령이 항상 "이 버전에선 일시 중지 불가" 경고만 낸다. pause를 실제 구현(coordinator에 drain 중지 플래그)하거나, 오해를 줄이려 명령을 제거/문구 조정.

### C2. `extension.ts` 배선 유닛 테스트 부재 **[Med]**
- 알림 IIFE·명령 핸들러·deps 구성은 smoke로만 검증된다. 이번 "수집 상태 뷰가 비어있던 버그"(getChildren `[]`)도 provider 테스트가 없어 빠져나갔다(사용자 신고로 발견). 최소한 provider·알림 가드 로직은 vscode mock으로 유닛 테스트 권장.

### C3. 수집 상태 뷰 표현 확장 **[Low]**
- 현재 1행(전체 건강도). 클라이언트별 분해·마지막 이벤트 시각·pending 봉투 수·"drain 필요" 힌트까지 노출하면 진단성이 오른다(`hooks status`가 이미 그 데이터를 계산함).

## D. 문서/온보딩

### D1. 루트 README / 마켓플레이스 리스팅 부재 **[High]**
> **범위 정정 (확장-only 배포):** CLI 무마찰-진입점 목적은 줄지만, **VS Code 마켓플레이스 등록엔 README가 필수**(리스팅 설명·스크린샷·프라이버시 고지). 방향을 "마켓플레이스 리스팅"으로 조정.
- 저장소에 최상위 README가 없어 신규 사용자/기여자가 진입 불가하고, 확장을 마켓플레이스에 올리려면 리스팅 문서가 반드시 필요하다.
- **제안**: README/확장 리스팅에 (1) 한 줄 소개 (2) 확장 설치 + **훅 자동설치([설치] 알림)** 흐름 (3) 스크린샷(비용×사용 매트릭스, 수집 상태 뷰) (4) **프라이버시**(로컬 전용·`tool_input`/`tool_response` 미저장·원본 로그 읽기 전용) 명시 (5) 무엇을 수집/안 하는지·끄는 법.

### D2. 훅 자동설치 사용자 문서 **[Low]**
- spec/plan은 있으나 사용자향 "훅이 뭘 수집/안 하나, 끄는 법" 설명이 lens-audit-plugin README에만 흩어져 있다. README나 확장 마켓플레이스 설명에 통합.

## F. 위험 (대부분 기존 문서화, 재확인)

- **로그 포맷 취약성**: 비공식 JSONL 파싱 — 클라이언트 버전업에 파서 파손 가능(어댑터 격리·parseErrors 계수로 국소화). Hook 우선 수집이 이 리스크의 공식 헤지.
- **OAuth 하드닝 이월**(BACKLOG): state 파라미터 검증 없음, 재로그인 redirect_uri 미검증.
- **대시보드 동결**(수용): 코드·테스트 유지, 신규 기능 없음. 잠재 동시성 결함(M8)은 수정 계획 없음.
- **npm 배포 안 됨**: 확장(.vsix)·CLI·플러그인 모두 로컬 설치만. 마켓플레이스/npm 퍼블리시는 별도 태스크(설계 로드맵의 "무마찰 진입점"이 실현되려면 최소 CLI npm 배포 필요).
