# 문서 사이트 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AIMET 문서 수준의 풀 문서 사이트를 VitePress로 `website/`에 만들고 GitHub Pages로 배포한다.

**Architecture:** 루트 `website/`에 workspaces 밖 독립 VitePress 프로젝트. 영어 기본 + `ko/` locale 골격, 다크 기본. 내용은 루트 README와 패키지 README에서 이관하고 README는 슬림화한다.

**Tech Stack:** VitePress ^1.6.3 / GitHub Actions / GitHub Pages

**스펙:** `docs/superpowers/specs/2026-08-09-문서-사이트-design.md` (작성 원칙 7개 포함, 모든 페이지 태스크의 통과 기준)

## Global Constraints

- 본문 언어는 **영어** (CLAUDE.md 언어 규칙, 배포 문서).
- `website/`는 루트 `package.json` workspaces에 **넣지 않는다**. 루트 `npm test`·빌드 체인 불변.
- 내용의 진실 소스: 루트 `README.md`, `packages/lens-audit-plugin/README.md`,
  `packages/codex-plugin/README.md`, `packages/gemini-extension/README.md`,
  `packages/extension/README.md`, `MCP-Lens-설계문서-v2.md`(concepts 한정).
  **소스에 없는 명령·수치·동작을 지어내지 않는다. 확인 불가면 페이지에서 뺀다.**
- 스펙의 **작성 원칙 7개**가 모든 페이지의 통과 기준: 과업 순서 / 복붙 가능 코드 /
  기대 출력 병기 / `::: code-group` 탭 분기 / 한 화면 한 절 / Quick Start는 첫 스캔 성공까지 /
  첫 문단은 도착점 선언.
- 판정 명령: `cd website && npm run docs:build`. VitePress는 dead link에서 빌드가 실패하므로
  빌드 성공이 링크 검증이다.
- 커밋 메시지는 한국어, 태스크 단위 원자적.

### Task 2: quick-start.md

**Files:** Modify: `website/quick-start.md`
**Interfaces:** Consumes: Task 1의 사이드바 경로. Produces: 없음 (말단 페이지).

구성 (스펙 확정, README "Installation"·"CLI usage" 절이 소스):

1. **Requirements**: Node.js 20+, VS Code 1.90+(확장 사용 시). 표 없이 리스트 2줄.
2. **Install**: `::: code-group` 탭 2개 — "VS Code extension (recommended)" 탭에 README의
   `.vsix` 빌드·설치 4줄 블록, "CLI" 탭에 `npm install && npm run build` + `npm link -w @mcp-lens/cli`.
   CLI 탭에는 README의 `npx mcp-lens` 제3자 패키지 경고를 `::: warning`으로 포함.
3. **Verify**: 확장은 "재시작 후 activity bar에 MCP Lens 아이콘과 온보딩 워크스루가 뜬다" 문장,
   CLI는 `npx --no-install mcp-lens --help` 실행과 기대 출력 첫 줄.
4. **Your first audit in 5 minutes**: `mcp-lens scan` → 동작 설명은 README 문장 재사용
   ("stdio 서버를 잠깐 기동해 `tools/list`만 호출, LLM 토큰 소비 없음"), 터미널 출력 블록은
   지어내지 않는다. `mcp-lens report` → cost × usage 매트릭스 실제 출력 발췌.
   훅 설치는 다음 단계로 가이드 페이지 링크. 도착점: "매트릭스를 봤다".

**실행 출력 채취 규칙 (Task 2·4 공통):** 실제 출력은 **읽기 전용인 `report`만** 실행해 얻는다
(README Known limitations: `report` is read-only and always safe). **`scan`·`auth`는 절대 실행하지
않는다** — 확장이 살아 있으면 라이터 충돌로 기록이 유실될 수 있다. 실행은 워크스페이스 빌드가
있는 **원래 프로젝트 루트**에서 `npx --no-install mcp-lens report`로 한다 (worktree에는
node_modules가 없다). 출력에 로컬 서버 이름 등 공개 부적절 항목이 있으면 서버 이름만
`weather-tools` 식 일반 명칭으로 치환하고 구조는 유지한다.

### Task 8: 배포 워크플로

**Files:** Create: `.github/workflows/docs.yml`

전량:

```yaml
name: docs

on:
  push:
    branches: [main]
    paths: ['website/**', '.github/workflows/docs.yml']
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm install
        working-directory: website
      - run: npm run docs:build
        working-directory: website
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with:
          path: website/.vitepress/dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```
