# 상태바 지표 재정의 — 설계

작성일: 2026-07-21
상태: **착수 확정** — 결정 문서(`docs/decisions/2026-07-21-상태바-지표-재정의.md`)의 4개 미결정을 확정하고 구현 설계를 세운다.

## 목표

상태바를 "지연 로딩으로 아낀 토큰"(`saved`)에서 **"우리가 낭비로 판단한 툴의 개수 + 그 정의 비용의 합"**으로 바꾼다. 현행 `saved` 지표는 인센티브가 역방향이다 — 안 쓰는 MCP 서버를 추가하면 수치가 올라간다(결정 문서 "결함 1"). 낭비 지표는 정리하면 줄고 낭비를 추가하면 늘어난다.

```
변경 전:  Lens: 24 calls · 16.8k saved
변경 후:  Lens: 낭비 10툴 · 15.3k     (낭비 0일 때: Lens: 낭비 없음 ✓)
```

## 확정된 결정 (결정 문서 "착수 시 정할 것")

| 항목 | 확정 | 근거 |
|---|---|---|
| 문구(낭비 있음) | `Lens: 낭비 {n}툴 · {k}` | 결정 문서 초안. 간결·한 줄 적합 |
| 문구(낭비 0) | `Lens: 낭비 없음 ✓` | 깨끗한 상태를 긍정적으로 확인, 도구 생존 신호 |
| 클라이언트 분리 | **전체 합계** | 상태바는 한 줄. `buildReport` totals가 이미 합산값. 클릭 시 리포트가 클라이언트별로 분해 |
| 축 | **세션당** (정의 토큰) | 정의 비용은 매 세션 반복되는 상주 비용. 조치 지표 성격상 세션당이 자연스러움 |

## 집계 정의

세 개념 중 **② 낭비로 판단**을 집계한다(결정 문서 "집계 대상은 판단이지 확정이 아니다").

| | 정의 | 상태바 표시 |
|---|---|---|
| ① 호출 0회 | `callCount === 0` | ✗ (미사용 신규 툴과 낭비를 구분 못 함) |
| ② **낭비로 판단** | `action`이 `remove` \| `filter-server` | ✓ **집계 대상** |
| ③ 낭비로 확정 | ② 중 `confidence !== 'low'` (`act` 버킷) | ✗ (현재 전 클라이언트 0 → 항상 0이 됨) |

## 아키텍처 — 새 집계 없이 `buildReport` 재사용

`② 낭비 판단`은 이미 리포트 모델(`report/rollup.ts`)이 계산한다. `remove`/`filter-server`는 confidence에 따라 두 버킷으로 나뉘며(`act`=확정, `candidate`=후보), 둘을 합치면 ②가 된다.

```
wasteToolCount = totals.actToolCount        + totals.candidateToolCount
wasteTokens    = totals.actPerSessionTokens + totals.candidatePerSessionTokens
```

- `totals`는 `buildReport(input, opts).totals` (`ReportTotals`, `report/model.ts:65`).
- `actPerSessionTokens`/`candidatePerSessionTokens`는 `sumDefinitionTokens` — **세션당 정의 토큰**이라 "세션당" 결정과 일치.
- `buildReport`는 이미 `splitByClient`(클라이언트 귀속 필터) + `visibleMatrixRows`를 거친다 → gemini 유령 92툴이 제거된 상태. 실측 `claude-code 10툴·15,267tok`와 일치.
- `totals`는 클라이언트별 롤업의 합산이므로 "전체 합계" 결정과 일치. `collapsed` 여부와 무관하게 카운트된다(`rollupClient`가 `rowsByBucket`에서 직접 산출).

**별도 집계 함수를 만들지 않는다.** 상태바·리포트가 같은 `buildReport`를 진실의 단일 출처로 공유한다.

## 컴포넌트별 변경

### `packages/extension/src/statusBar.ts` — `formatStatus` 재작성

시그니처를 `(callCount, savedTokens)` → `(wasteToolCount, wasteTokens)`로 교체.

```ts
export function formatStatus(wasteToolCount: number, wasteTokens: number): string {
  if (wasteToolCount === 0) return 'Lens: 낭비 없음 ✓';
  const k = wasteTokens >= 1000
    ? `${(Math.floor(wasteTokens / 100) / 10).toFixed(1)}k`
    : `${wasteTokens}`;
  return `Lens: 낭비 ${wasteToolCount}툴 · ${k}`;
}
```

- 기존 k-포맷(floor 방식)을 그대로 유지 → 15,267은 `15.2k`로 렌더(결정 문서의 "15.3k"는 근사치). 코드베이스 일관성 우선.

### `packages/extension/src/extension.ts` — 호출부·import

- `:120` 교체:
  ```ts
  const totals = buildReport(input, { days: reportDays() }).totals;
  item.text = formatStatus(
    totals.actToolCount + totals.candidateToolCount,
    totals.actPerSessionTokens + totals.candidatePerSessionTokens);
  item.tooltip = wasteTooltip(totals); // 아래
  ```
  `buildReport`는 이미 `:228`(`showReport`)이 import·사용 중이라 신규 import 불필요. totals 계산은 `opts`에 의존하지 않으므로 최소 opts로 충분.
- `:3` import에서 `sessionSavings` 제거(이 파일에서 유일 사용처였음). `sessionSavings` **export 자체는 유지** — `packages/cli`·`packages/dashboard`가 계속 사용한다.

### 툴팁 (한 줄 지표의 모호함 보완)

"낭비 10툴"의 의미를 hover로 설명. `extension.ts`에 소형 헬퍼:

- 낭비 있음: `낭비로 판단한 툴 {n}개 · 세션당 정의 {k}토큰\nremove/filter-server 판정 · 클라이언트 귀속 적용\n클릭 → 상세 리포트`
- 낭비 0: `낭비로 판단한 툴 없음 · 클릭 → 상세 리포트`

## 테스트

`packages/extension/test/statusBar.test.ts` 전면 교체(기존은 옛 시그니처):

- `formatStatus(0, 0)` → `Lens: 낭비 없음 ✓`
- `formatStatus(0, 5000)` → `Lens: 낭비 없음 ✓` (툴 0이면 토큰 무관)
- `formatStatus(10, 15267)` → `Lens: 낭비 10툴 · 15.2k`
- `formatStatus(1, 1000)` → `Lens: 낭비 1툴 · 1.0k` (k 경계)
- `formatStatus(3, 680)` → `Lens: 낭비 3툴 · 680` (1000 미만 원시값)

②(act+candidate) 집계 정확성은 기존 `rollup` 테스트가 이미 커버하므로 신규 테스트 불필요.
